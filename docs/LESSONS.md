# LESSONS

Журнал граблей. Читается в начале каждой сессии вместе с `CLAUDE.md`. Порядок — от новых к старым, чтобы свежее попадало в контекст первым.

**Формат записи:**

```
## L-042 · B5.2 · 2026-10-03 · выравнивание
**Симптом:** что наблюдалось.
**Причина:** что было на самом деле.
**Правило:** что теперь делаем всегда.
**Закреплено:** тест или файл, который не даст повториться.
```

**Когда писать:** потратили больше 30 минут на то, что в итоге оказалось простым; нашли неочевидное поведение библиотеки или API; приняли решение, о котором через месяц спросят «почему так». Сюда же — ошибки Claude Code по ходу разработки (неверное предположение, сломанная сборка, нарушенное правило `CLAUDE.md`), если они стоили времени или меняют правило работы. Не пишем: «забыл импорт», «опечатка», «не запустил тесты».

**Держим файл ≤ 150 строк.** Уроки, ставшие правилами в `CLAUDE.md` или закреплённые тестом, сворачиваем в одну строку в разделе «Архив» внизу.

## L-035 · M4.10 · 2026-10-11 · невидимые символы
**Симптом:** `ruff format` показал в `tests/test_subtitles.py` строку вида `"1\r\n…"`, где перед `1` стоял
невидимый символ; в `subtitles.py` — `.replace("<невидимый>", "")` вместо `.replace("\ufeff", "")`. Тесты зелёные.
**Причина:** при записи файла инструментом escape `\ufeff` в тексте раскрылся в сам символ BOM (U+FEFF), а `\r\n`
остались как есть. Код работал, но правка такого места руками незаметно ломает его.
**Правило:** невидимые и служебные символы в коде и тестах (BOM, NBSP, ZWJ) — только escape-последовательностью;
после записи такого файла — `grep -c $'\xef\xbb\xbf'` (и для NBSP `$'\xc2\xa0'`) по нему.
**Закреплено:** `pipeline/research/subtitles.py` и `tests/test_subtitles.py` — escape `\ufeff`.

## L-034 · M4.7 · 2026-10-08 · вывод живого скрипта
**Симптом:** первый живой прогон Playwright упал, но причину не увидеть: `| tail -30` показал только хвост дампа —
Playwright печатает в журнал шага значение `fill()`, а это весь JSON плана (3 234 строки). Четыре повторных прогона,
в том числе на холодном vite, прошли; причина первого так и не установлена.
**Причина:** вывод скрипта смотрелся хвостом, а не сохранялся целиком.
**Правило:** живой скрипт пишет вывод в файл (`> run.log 2>&1`), смотреть — без серых строк журнала
(`grep -v $'\x1b\[2m'`); каждый прогон — на новом выпуске, чтобы следы прошлого не маскировали ошибку.
**Закреплено:** рецепт `live-check-required` в памяти.

## L-033 · M4.6 · 2026-10-08 · поле ответа без фронта
**Симптом:** (до записи кода) `approved_version` в `Project` и пометка моста в смете пресета стали бы в TS
обязательными: моки `mocks/api.ts` собраны через `satisfies Project` / `FormatPreview`, `pnpm build` упал бы, а
`frontend/**` в бэкенд-этапе не трогается.
**Причина:** `ApiJsonSchema` делает поле ответа с умолчанием обязательным (L-019); исключение — поле с
`exclude_if`: его может не быть в ответе.
**Правило:** новое поле существующей модели ответа в этапе без фронта — `Field(default=None, exclude_if=_is_none)`,
в TS оно `?:`. Обязательным его делает этап фронта вместе с моками. После `typegen` — `pnpm -C frontend build`.
**Закреплено:** `models/project.py` (`approved_*`), `pipeline/script/estimate.py` (`StageCost.via`).

## L-032 · M4.4 · 2026-10-07 · тело ошибки
**Симптом:** (при чтении кода, до первого запуска) отказ моста на экране показал бы «Бэкенд ответил 422 без описания
ошибки», хотя бэкенд прислал текст, подсказку и ошибки по кадрам.
**Причина:** `HTTPException` кладёт описание в `detail`, а обработчик `BridgeAnswerError` (M4.1) пишет `BridgeError`
в корень тела. Клиент читал только `detail`; фронт до M4.4 этот путь не вызывал, и тесты бэкенда разрыва не видели.
**Правило:** новый формат тела ошибки на бэкенде (свой обработчик исключений) — вместе с тестом `client.test.ts` на
это тело. Описание ошибки клиент берёт через `detailOf`: `detail`, а без него — корень с `message`.
**Закреплено:** `api/client.ts` (`detailOf`, `bridgeError`), `api/__tests__/client.test.ts` («422 моста»).

## L-031 · M4.3 · 2026-10-07 · typegen и режимы
**Симптом:** после регистрации `ProjectPatch` в группе `project` упал `test_groups_have_every_model…`: определения
`EpisodeBrief` в схеме не стало, вместо него — `EpisodeBrief-Input` и `EpisodeBrief-Output` (так же `ShotOverride`,
`SfxSpec`). TS-тип `EpisodeBrief` сменил бы имя.
**Причина:** `models_json_schema` по группе с моделями в двух режимах (ответ — serialization, тело — validation) делит
общую подмодель на две, если её схемы в режимах различаются. У нас различаются всегда, когда есть поле с умолчанием:
`ApiJsonSchema` делает его в ответе обязательным (L-019).
**Правило:** тело запроса, разделяющее подмодели с ответами, — в своей группе `gen_schema` (`project_patch`).
Суффикс `-Input`/`-Output` в `$defs` — сигнал разнести модели, а не переименовывать типы на фронте.
**Закреплено:** `tools/gen_schema.py` (`API_GROUPS["project_patch"]`), `tests/test_gen_schema.py`.

## L-028 · M3.7 · 2026-09-29 · порядок по регистрации
**Симптом:** в окне горячих клавиш «Помощь» встала раньше «Панелей», а для выпуска из кэша — наоборот.

## L-027 · M3.7 · 2026-09-29 · e2e на моках
**Симптом:** glob `**/api/**` в `page.route` перехватил и модули dev-сервера (`/src/api/queries.ts`) — приложение не
стартовало. Эталон M1.6 `10-states` оказался пустой рабочей зоной — снимок до загрузки чанка каталога.
**Причина:** glob сопоставляется со всем URL. `toHaveScreenshot` ждёт двух одинаковых кадров, а пустой экран стабилен.
**Правило:** мок API — предикат `pathname.startsWith('/api/')`, незамоканный путь валит тест. Перед снимком — ожидание
содержимого экрана. При пересъёмке каждый изменившийся эталон разбирается по зонам: шапка, тело, статус-строка.
**Закреплено:** `frontend/e2e/api.ts`, `open()` в `frontend/e2e/visual.spec.ts`.

## L-026 · M3.6 · 2026-09-29 · живая проверка
**Симптом:** три пустых захода до живого прогона: запуск с `rm -rf` в той же строке отклонён, MCP-браузер Playwright
не стартовал (нет `/opt/google/chrome`), `pkill -f vite` убил оболочку своей же команды (exit 144), Vite остался на :5173.
**Причина:** рецепт живой проверки лежит в памяти (`live-check-required`), а прочитана была только строка индекса.
**Правило:** перед живой проверкой открыть рецепт целиком. Данные — новый каталог в scratchpad, без `rm -rf`; браузер —
`node`-скрипт на `@playwright/test` из `frontend/node_modules`; остановка — TaskStop или `kill` PID из `ss -ltnp`.
**Закреплено:** строка индекса памяти называет рецепт.

## L-022 · M3.1 · 2026-09-26 · проверка и тексты ошибок
**Симптом:** этап закрыт без живой проверки (запуск uvicorn отклонили — отчитался тестами); прогон по просьбе
пользователя нашёл: 422 на пустое название — две английские ошибки, одна «Input should be None».
**Причина:** ограничения на `str | None` pydantic проверяет в каждой ветке объединения и отчитывается за все;
`ValueError` из валидатора получает префикс «Value error, ». Тесты сверяли код 422, не текст.
**Правило:** «Команды проверки» этапа выполняются вживую (сервер на временном `STUDIO_DATA_DIR`); отклонённый запуск —
спросить, а не заменять тестами. Текст ошибки для пользователя — `PydanticCustomError` из одной функции после
разбора типа; тест проверяет `msg`, а не только статус.
**Закреплено:** `api/episodes.py::_clean_title`, `tests/test_api_episodes.py::test_errors_are_one_readable_message`.

## L-007 · B2A · 2026-09-11 · эпоха
**Симптом:** (упреждающе) в исторический кадр приезжают предметы не из той эпохи, и замечается это уже на смонтированном ролике.
**Причина:** модель достраивает «типичный исторический антураж» по общему представлению, а не по конкретному году и региону.
**Правило:** у каждого периода есть обязательный непустой список `forbidden`, он идёт в negative каждого кадра этого периода и служит чеклистом для автоматической проверки после генерации. Пустой `forbidden` не проходит валидацию.
**Закреплено:** валидатор в B2A.1, проверка в B2A.5.
