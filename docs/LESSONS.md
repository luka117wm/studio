# LESSONS

Журнал граблей. Читается в начале каждой сессии вместе с `CLAUDE.md`. Порядок — от новых к старым, чтобы свежее попадало в контекст первым.

**Формат записи:**

```
## L-042 · B5.2 · 2026-10-03 · выравнивание
**Симптом:** что наблюдалось.
**Причина:** что было на самом деле.
**Правило:** что теперь делаем всегда.
**Закреплено:** тест или файл, который не даст повториться.
```

**Когда писать:** потратили больше 30 минут на то, что в итоге оказалось простым; нашли неочевидное поведение библиотеки или API; приняли решение, о котором через месяц спросят «почему так». Сюда же — ошибки Claude Code по ходу разработки (неверное предположение, сломанная сборка, нарушенное правило `CLAUDE.md`), если они стоили времени или меняют правило работы. Не пишем: «забыл импорт», «опечатка», «не запустил тесты».

**Держим файл ≤ 150 строк.** Уроки, ставшие правилами в `CLAUDE.md` или закреплённые тестом, сворачиваем в одну строку в разделе «Архив» внизу.

## L-012 · M1.6 · 2026-09-19 · снимки
**Симптом:** первые эталоны Playwright для трёх ширин перезаписывали друг друга — один файл на экран.
**Причина:** `snapshotPathTemplate` без `{projectName}`: проекты-ширины пишут в одно имя.
**Правило:** шаблон эталона включает `{arg}-{projectName}-{platform}`; источники флаки гасятся до порога — `page.clock.install()` (таймеры: обратный отсчёт, автоскрытие тостов), `animations: 'disabled'`, `reducedMotion`. Порог не поднимать.
**Закреплено:** `frontend/playwright.config.ts`, `e2e/visual.spec.ts`; три прогона подряд — 0 расхождений.

## L-011 · M1.6 · 2026-09-19 · макеты
**Симптом:** в `layout.md` нет ширин для «Идей» (300 / 340), а правая колонка «Канона» в артборде 480 при лимите 280–420; артборд 6 — не экран, а лист вариантов инспектора.
**Причина:** handoff писался по основным экранам; артборды и таблица ширин расходятся между собой.
**Правило:** ширины берутся из `layout.md`; если там нет — замер DOM артборда (не на глаз) с пометкой «макет» в `docs/visual_review.md`; при конфликте артборда и `layout.md` побеждает `layout.md`, конфликт — в review.
**Закреплено:** `docs/visual_review.md`, комментарии в `app/ScreenLayout.tsx`.

## L-010 · M1.2 · 2026-09-18 · тесты
**Симптом:** Popover и DropdownMenu в vitest + jsdom переносят фокус внутрь слоя, а в Chrome фокус остаётся на триггере.
**Причина:** до замера позиции слой стоял с `visibility: hidden`. Браузер не фокусирует скрытые элементы; jsdom раскладку и видимость не моделирует и фокусирует что угодно — тест зелёный, продукт сломан.
**Правило:** всплывающий слой до замера стоит в (0, 0), не hidden (замер в layout-эффекте, до отрисовки). Поведение фокуса и оверлеев проверяется в реальном браузере (Playwright); jsdom — только для логики и aria.
**Закреплено:** `ui/internal/useAnchorPosition.ts` (`layerStyle`); браузерная проверка — визуальная приёмка M1.6.

## L-009 · M1.2 · 2026-09-18 · tailwind
**Симптом:** классы штриховки для `::after` loading-кнопки компилируются в тесте через `compile()`, а в сборке их нет.
**Причина:** сканер Tailwind v4 берёт кандидаты из исходников как есть; класс `'after:' + cls`, склеенный в рантайме, он не видит.
**Правило:** имена утилит — только литеральные строки, вариант вместе с классом. Проверка: прогнать все строковые токены `src/ui` через `compile()` и посмотреть, какие не дали CSS.
**Закреплено:** `ui/internal/hatch.ts` — два литерала; проверочный тест «каждый класс даёт CSS» — хвост M1.6.

## L-008 · B2A · 2026-09-11 · канон
**Симптом:** (упреждающе, по опыту ручного пайплайна) персонаж «плывёт» от кадра к кадру, а между эпизодами канал выглядит как три разных канала.
**Причина:** стиль и внешность описывались текстом заново в каждом промпте. Любая переформулировка — другой человек и другая картинка. Плюс модель без референса не обязана повторять лицо.
**Правило:** канон живёт на уровне канала и версионируется; у каждого облика есть лист из шести опорных портретов, который подаётся референсом в каждый кадр; итоговый промпт собирает код в фиксированном порядке (принцип 13). Эпизод прибит к версиям канона и не меняется при их обновлении.
**Закреплено:** `CLAUDE.md` принципы 13 и 14, тест детерминированности промпта в B2A.3, тест иммутабельности версий в B2A.1.

## L-007 · B2A · 2026-09-11 · эпоха
**Симптом:** (упреждающе) в исторический кадр приезжают предметы не из той эпохи, и замечается это уже на смонтированном ролике.
**Причина:** модель достраивает «типичный исторический антураж» по общему представлению, а не по конкретному году и региону.
**Правило:** у каждого периода есть обязательный непустой список `forbidden`, он идёт в negative каждого кадра этого периода и служит чеклистом для автоматической проверки после генерации. Пустой `forbidden` не проходит валидацию.
**Закреплено:** валидатор в B2A.1, проверка в B2A.5.

## L-006 · B0 · 2026-09-11 · процесс
**Симптом:** длинные сессии заканчивались тем, что модель забывала форму данных и начинала выдумывать поля.
**Причина:** автокомпакт пересказывает контракт вместо того, чтобы его сохранить.
**Правило:** `/clear` между микроэтапами, не `/compact`. Контракт всегда лежит в `docs/`, а не в истории чата. Task-файл перечисляет пути явно — «посмотри проект» запрещено.
**Закреплено:** `CLAUDE.md`, «Как работаем».

## L-005 · B8 · 2026-09-11 · рендер
**Симптом:** (упреждающе, по опыту прошлых прототипов) движение камеры через `ffmpeg zoompan` дрожит на медленном наезде.
**Причина:** zoompan считает смещение в целых пикселях, на 0.08 силы за 5 секунд шаг округления виден как рывки раз в несколько кадров.
**Правило:** движение считает компоновщик на float-матрицах (OpenCV warpAffine) по той же математике, что и превью. FFmpeg отвечает только за декод, энкод, аудио и субтитры.
**Закреплено:** `CLAUDE.md` принцип 3, WYSIWYG-тест B8.4.

## L-004 · B8 · 2026-09-11 · цвет
**Симптом:** (упреждающе) рендер выглядит темнее и бледнее превью на тех же кадрах.
**Причина:** без явных флагов colorspace/primaries/trc энкодер помечает поток как неопределённый, плееры трактуют его по-своему.
**Правило:** кадры в sRGB, энкод в yuv420p с явными BT.709 флагами. Любая новая команда ffmpeg копирует этот набор флагов.
**Закреплено:** `CLAUDE.md` принцип 4.

## L-003 · B0.3 · 2026-09-11 · хранилище
**Симптом:** (перенос с Leen & Green) при падении в момент записи файл состояния оставался обрезанным.
**Причина:** запись поверх существующего файла не атомарна.
**Правило:** только temp-файл в той же папке → fsync → rename. Ни одного `open(path, "w")` для файлов состояния.
**Закреплено:** тест на 500 прерванных записей в B0.3.

## L-002 · — · 2026-09-11 · окружение
**Симптом:** (перенос с Leen & Green) файловые операции из WSL по путям `/mnt/c/...` работают в разы медленнее и ломают права.
**Причина:** мост 9p между файловыми системами.
**Правило:** все рабочие данные в файловой системе WSL (`~/studio/data`). В Windows отдаются только экспортированные файлы, с конвертацией пути в UNC `\\wsl.localhost\Ubuntu\...` при экспорте в Premiere.
**Закреплено:** `storage/paths.py`, экспорт FCP7 в B9.2.

## L-001 · — · 2026-09-11 · деньги
**Симптом:** (перенос с Leen & Green, где это была цена в копейках) расчёты стоимости, размазанные по коду, расходятся между показом и списанием.
**Причина:** два места расчёта — две правды.
**Правило:** единственная точка расчёта стоимости — `cost/`. Цены только из `config/pricing.yaml`, накопление в микродолларах, округление только на отображении. Оценка до вызова и фактическая запись после вызова используют одну функцию.
**Закреплено:** `CLAUDE.md` принцип 6, тесты B0.5.
