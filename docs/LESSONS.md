# LESSONS

Журнал граблей. Читается в начале каждой сессии вместе с `CLAUDE.md`. Порядок — от новых к старым, чтобы свежее попадало в контекст первым.

**Формат записи:**

```
## L-042 · B5.2 · 2026-10-03 · выравнивание
**Симптом:** что наблюдалось.
**Причина:** что было на самом деле.
**Правило:** что теперь делаем всегда.
**Закреплено:** тест или файл, который не даст повториться.
```

**Когда писать:** потратили больше 30 минут на то, что в итоге оказалось простым; нашли неочевидное поведение библиотеки или API; приняли решение, о котором через месяц спросят «почему так». Сюда же — ошибки Claude Code по ходу разработки (неверное предположение, сломанная сборка, нарушенное правило `CLAUDE.md`), если они стоили времени или меняют правило работы. Не пишем: «забыл импорт», «опечатка», «не запустил тесты».

**Держим файл ≤ 150 строк.** Уроки, ставшие правилами в `CLAUDE.md` или закреплённые тестом, сворачиваем в одну строку в разделе «Архив» внизу.

## L-024 · M3.3 · 2026-09-26 · тесты с кэшем запросов
**Симптом:** после `act(() => source.emit(...))` статус-строка ещё старая; после теста — необработанные
`ReferenceError: EventSource is not defined`.
**Причина:** TanStack Query рассылает изменения кэша через `setTimeout(0)`, не синхронно с `act`. Второе:
`afterEach(vi.unstubAllGlobals)` файла идёт раньше `cleanup` из `vitest.setup.ts` — снимок джобов, пришедший между
ними, подписывается на уже снятый фейк.
**Правило:** после записи в кэш — `waitFor`/`findBy`, результат мутации — из `mutateAsync`, не из `result.current`. В
файлах с фейками сети `afterEach`: сначала `cleanup()`, потом `vi.unstubAllGlobals()`.
**Закреплено:** `app/__tests__/shell.test.tsx`, `keyboard.test.tsx`, `api/__tests__/queries.test.tsx`.

## L-023 · M3.3 · 2026-09-26 · прокси Vite и мёртвый бэкенд
**Симптом:** живая проверка: uvicorn остановлен при открытом экране — «Бэкенд недоступен» не появляется ни через
30 с; после перезагрузки страницы тоже нет.
**Причина:** прокси Vite (`/api` → `:8000`) отвечает на запрос к мёртвому бэкенду `502` с пустым `text/plain`, а не
обрывом — клиент видел ошибку бэкенда 502, а не `status 0`. А начатый поток SSE прокси браузеру не обрывает: он
«открыт» и молчит, `EventSource` не видит ни ошибки, ни конца.
**Правило:** 502/503/504 без JSON-тела — «ответа бэкенда не было» (`status 0`): свои ошибки бэкенд всегда отдаёт JSON
с `detail`. Живость потока — по heartbeat: тишина дольше 35 с — переподключение; обрыв потока — проверочный
перезапрос экрана, открытие — сброс запросов. Тестовая заглушка «бэкенд лежит» отвечает как прокси, а не
`TypeError`. Сценарии «бэкенд лёг/поднялся» проверяются вживую через прокси, не только в jsdom.
**Закреплено:** `api/client.ts` (`GATEWAY_STATUSES`), `api/sse.ts` (`SILENCE_LIMIT_MS`), `api/live.ts` (`onState`),
`client.test.ts`, `sse.test.ts`, `shell.test.tsx` («бэкенд упал при открытом экране»).

## L-022 · M3.1 · 2026-09-26 · проверка и тексты ошибок
**Симптом:** этап закрыт без живой проверки (запуск uvicorn отклонили — отчитался тестами); прогон по просьбе
пользователя нашёл: 422 на пустое название — две английские ошибки, одна «Input should be None».
**Причина:** ограничения на `str | None` pydantic проверяет в каждой ветке объединения и отчитывается за все;
`ValueError` из валидатора получает префикс «Value error, ». Тесты сверяли код 422, не текст.
**Правило:** «Команды проверки» этапа выполняются вживую (сервер на временном `STUDIO_DATA_DIR`); отклонённый запуск —
спросить, а не заменять тестами. Текст ошибки для пользователя — `PydanticCustomError` из одной функции после
разбора типа; тест проверяет `msg`, а не только статус.
**Закреплено:** `api/episodes.py::_clean_title`, `tests/test_api_episodes.py::test_errors_are_one_readable_message`.

## L-021 · M3.1 · 2026-09-26 · sqlite и транзакции
**Симптом:** с обычным `BEGIN` второй из двух параллельных `POST /api/episodes` падает с `database is locked`, хотя
`busy_timeout` 5 с, а первый держит блокировку 0,2 с.
**Причина:** отложенная транзакция сначала читает (снимок WAL), потом пишет; если другой писатель закоммитил после её
снимка, SQLite отвечает `SQLITE_BUSY` сразу — ждать бесполезно, снимок уже устарел.
**Правило:** «прочитал — решил — записал» (выбор номера, проверка занятости) — только в `BEGIN IMMEDIATE`: блокировка
записи берётся до чтения, второй писатель ждёт в `busy_timeout`, а не падает.
**Закреплено:** `api/episodes.py::insert_episode`, `tests/test_api_episodes.py::test_parallel_creates_get_distinct_ids`
(с `BEGIN` падает — проверено).

## L-020 · M3.1 · 2026-09-26 · typegen
**Симптом:** в `@/types/episode` у `Episode` нет поля `title`, в `@/types/director` — `Section.title` и `Source.title`;
`typegen:check` зелёный — он сверяет с тем же ошибочным выводом.
**Причина:** снятие заголовков полей (L-019) удаляло любой ключ `title`, в том числе имя поля в `properties`;
json-schema-to-typescript молча пропускает поле из `required`, которого нет в `properties`.
**Правило:** при обходе JSON Schema ключи `properties` — имена полей, их не фильтровать. Генерация проверяется не
только «файлы не устарели», но и типовым тестом на поле-ловушку.
**Закреплено:** `frontend/scripts/typegen.mjs::stripFieldTitles`, `src/api/__tests__/types.test.ts` (`tsc -b` в сборке).

## L-019 · M2.7 · 2026-09-25 · typegen
**Симптом:** в первых сгенерированных типах поля ответа со значением по умолчанию вышли необязательными
(`cost_usd_micro?`, `JobSummary.total?`), хотя сервер отдаёт их всегда; `title` каждого поля json-schema-to-typescript
превращал в отдельный именованный тип (`Status`, `Kind`…), и они сталкивались между моделями.
**Причина:** pydantic в режиме serialization делает поле с умолчанием обязательным только с флагом
`json_schema_serialization_defaults_required`; json-schema-to-typescript делает именованным типом любую подсхему с
`title`. И ещё: `$id` внутри `$defs` меняет базовый URI подсхемы — ссылки `#/$defs/…` в ней ломаются.
**Правило:** ответы API выгружаются генератором `ApiJsonSchema` (все поля обязательны), тела запросов — в режиме
validation; `title` остаётся только у определений; `$id` — на файл, не на модель.
**Закреплено:** `tools/gen_schema.py`, `frontend/scripts/typegen.mjs`, `tests/test_gen_schema.py`.

## L-015 · M2.4 · 2026-09-21 · stale
**Симптом:** задание M2.4 перечисляло VO среди изменений, а приёмка требовала «ровно 2 кадра stale» при фикстуре с
двумя изменёнными кадрами и одним изменённым VO — либо три stale, либо VO не stale.
**Причина:** `stale` — статус картинки, а VO, движение, переход и SFX картинку не трогают; их смену голос и рендер
и так увидят по хэшу входов (принцип 8). Делать кадр stale по любому изменению — значит гонять пользователя
перерисовывать то, что не изменилось.
**Правило:** `stale` только когда картинка перестала соответствовать плану (промпт, облики, эпоха, крупность, версии
канона) или план конфликтует с ручной блокировкой (`prompt_locked`, `duration_locked`, `user_override`). Остальное —
строка в отчёте импорта без смены статуса. Список полей — `STALE_FIELDS` в `pipeline/director_import/stale.py`,
расширять его, а не размазывать условия по мёрджу.
**Закреплено:** `tests/test_director_import.py::test_second_version_merges_stale_added_removed` (VO-кадр в отчёте,
но `queued`); раздел «Импорт и версии» в `docs/director_schema.md`.

## L-008 · B2A · 2026-09-11 · канон
**Симптом:** (упреждающе, по опыту ручного пайплайна) персонаж «плывёт» от кадра к кадру, а между эпизодами канал выглядит как три разных канала.
**Причина:** стиль и внешность описывались текстом заново в каждом промпте. Любая переформулировка — другой человек и другая картинка. Плюс модель без референса не обязана повторять лицо.
**Правило:** канон живёт на уровне канала и версионируется; у каждого облика есть лист из шести опорных портретов, который подаётся референсом в каждый кадр; итоговый промпт собирает код в фиксированном порядке (принцип 13). Эпизод прибит к версиям канона и не меняется при их обновлении.
**Закреплено:** `CLAUDE.md` принципы 13 и 14, тест детерминированности промпта в B2A.3, тест иммутабельности версий в B2A.1.

## L-007 · B2A · 2026-09-11 · эпоха
**Симптом:** (упреждающе) в исторический кадр приезжают предметы не из той эпохи, и замечается это уже на смонтированном ролике.
**Причина:** модель достраивает «типичный исторический антураж» по общему представлению, а не по конкретному году и региону.
**Правило:** у каждого периода есть обязательный непустой список `forbidden`, он идёт в negative каждого кадра этого периода и служит чеклистом для автоматической проверки после генерации. Пустой `forbidden` не проходит валидацию.
**Закреплено:** валидатор в B2A.1, проверка в B2A.5.

## L-003 · B0.3 · 2026-09-11 · хранилище
**Симптом:** (перенос с Leen & Green) при падении в момент записи файл состояния оставался обрезанным.
**Причина:** запись поверх существующего файла не атомарна.
**Правило:** только temp-файл в той же папке → fsync → rename. Ни одного `open(path, "w")` для файлов состояния.
**Закреплено:** тест на 500 прерванных записей в B0.3.

## L-002 · — · 2026-09-11 · окружение
**Симптом:** (перенос с Leen & Green) файловые операции из WSL по путям `/mnt/c/...` работают в разы медленнее и ломают права.
**Причина:** мост 9p между файловыми системами.
**Правило:** все рабочие данные в файловой системе WSL (`~/studio/data`). В Windows отдаются только экспортированные файлы, с конвертацией пути в UNC `\\wsl.localhost\Ubuntu\...` при экспорте в Premiere.
**Закреплено:** `storage/paths.py`, экспорт FCP7 в B9.2.

## L-001 · — · 2026-09-11 · деньги
**Симптом:** (перенос с Leen & Green, где это была цена в копейках) расчёты стоимости, размазанные по коду, расходятся между показом и списанием.
**Причина:** два места расчёта — две правды.
**Правило:** единственная точка расчёта стоимости — `cost/`. Цены только из `config/pricing.yaml`, накопление в микродолларах, округление только на отображении. Оценка до вызова и фактическая запись после вызова используют одну функцию.
**Закреплено:** `CLAUDE.md` принцип 6, тесты B0.5.
