# Слоты публикации и пресеты формата

Полоса слотов на экране «Выпуски», назначение выпуска в слот и смета выпуска для диалога «Новый выпуск».
Код: `backend/app/slots/schedule.py` (расписание, состояния — чистые функции), роутеры `backend/app/api/slots.py` и
`backend/app/api/formats.py`, проверка слота и `next_free` — `backend/app/api/episodes.py`, пресеты —
`backend/app/models/formats.py` и `config/formats.yaml`, миграция `005_slots.sql`. Типы фронта — `@/types/slot`,
пресет и смета — `@/types/channel`.

## Расписание (`data/schedule.json`)

Одно на оба канала: цель — выпуск раз в два дня на автора, Cursus и Otto чередуются в одной полосе.

```json
{ "anchor": "2026-09-26", "every_days": 2, "risk_days": 2 }
```

| Поле | Описание |
|---|---|
| `anchor` | любой день слота; слоты — `anchor + k × every_days` для любого целого `k`, в обе стороны |
| `every_days` | шаг слотов в днях, ≥ 1 |
| `risk_days` | будущий слот не дальше стольких дней с неготовым выпуском — риск, ≥ 0 |

- Файла нет — при первом чтении пишется атомарно с `anchor` = сегодня и значениями по умолчанию.
- Файл читается на каждый запрос: правка руками (до экрана настроек в M11) работает без перезапуска.
- Битый файл — 500 с путём и тем, что сделать (исправить или удалить).
- «Сегодня» — локальная дата машины: бэкенд и браузер на одном ноутбуке.
- Смена `anchor` или `every_days` не двигает выпуски: выпуск со старой датой вне нового расписания в полосе не
  виден — переназначьте его.

## Окно полосы — `GET /api/slots?from=&count=`

- Без `from` — 3 слота строго до сегодняшнего дня и остальные начиная с сегодняшнего; `count` по умолчанию 11
  (артборд 1: 3 прошлых, сегодня, 7 будущих). Если сегодня не день слота, прошлых всё равно 3.
- `from` округляется вверх до ближайшего слота; `count` — от 1 до 366.
- Выпуски окна читаются одним запросом.

Строка `Slot`:

| Поле | Тип | Описание |
|---|---|---|
| `date` | `YYYY-MM-DD` | день слота |
| `weekday` | 1…7 | ISO: 1 — понедельник, 7 — воскресенье; подпись пишет фронт |
| `episode_id`, `channel` | str \| `null` | выпуск в слоте |
| `state` | `published \| missed \| today \| filled \| empty` | см. ниже |
| `risk` | `{level, reason}` \| `null` | см. ниже |

### Состояние — первое подходящее

1. `published` — у выпуска статус `published`, при любой дате слота.
2. `today` — дата слота — сегодня.
3. `missed` — прошлый слот без опубликованного выпуска, в том числе пустой.
4. `filled` — будущий слот с выпуском; `empty` — без.

### Риск

Только у сегодняшнего и будущих слотов с неопубликованным выпуском.

| Условие | `level` |
|---|---|
| статус выпуска `failed` — на любом расстоянии | `failed` |
| статус `warning` — на любом расстоянии | `warning` |
| стадия до экспорта (`idea`, `script`, `generate`, `edit`) и до слота ≤ `risk_days` дней | `warning`, в день слота — `failed` |

`reason` — код по стадии, текст пишет фронт:

| Стадия | `reason` |
|---|---|
| `idea`, `script` | `script_not_ready` |
| `generate` | `shots_failed` при статусе `failed`, иначе `shots_incomplete` |
| `edit`, `export` | `not_exported` |

Стадия `publish` — выпуск экспортирован; риска нет, пока M10 не добавит свой код для сбоя публикации.

Сверено с артбордом 1 («сегодня» 11 сентября): `pirate` (монтаж, внимание, через 2 дня) — `warning`, `sweep`
(генерация, сбой, через 8 дней) — `failed`, `monastery` и `samurai` (идут, дальше `risk_days`) — без риска.
Таблица — `tests/test_slots.py::test_window_matches_artboard`.

## Назначение — `PUT /api/episodes/{id}/slot`

Тело `SlotAssign`: `{"date": "YYYY-MM-DD"}` или `{"date": null}` — снять со слота. Ответ — `EpisodeListItem`.

- Дата не из расписания — 422, `detail = {message, nearest}`: текст и четыре ближайших слота (два до, два после).
- Слот занят другим выпуском — 409: «Слот 23 сентября занят выпуском «…» (c02); снимите его со слота или выберите
  другой.»
- Повтор той же даты — 200 без изменений (`updated_at` не меняется). Перенос освобождает прежний слот.
- Прошлые слоты разрешены: опубликованный выпуск стоит в прошлом.
- В слоте один выпуск: проверка и запись — в `BEGIN IMMEDIATE`, под ней уникальный индекс `episodes(slot_date)`.

## Слот при создании — `POST /api/episodes`, поле `slot`

- `"next_free"` (по умолчанию) — первый слот строго после сегодняшнего, в котором нет выпуска. Сегодняшний не
  берётся: новый выпуск в нём сразу получил бы риск `failed` (решение при закрытии M3). Вручную — датой здесь или
  через `PUT` — сегодняшний назначается.
- `"YYYY-MM-DD"` — проверки те же, что у `PUT` (422, 409); при отказе ни строки, ни каталога не остаётся.
- `null` — без слота.
- Выбор слота идёт в той же транзакции, что выбор id: два одновременных «Создать» не получат один слот.
- Ответ несёт `slot_date` — тост «слот 23 сентября» берёт дату оттуда.

## Пресеты формата (`config/formats.yaml`) — `GET /api/formats?channel=`

Пресет — объёмы выпуска по формату канала (`channels.format`): подпись и пояснение для диалога, минуты
`{min, target, max}`, разделы, кадры, слов в минуту. Блок `estimate` — объём запросов сметы. Цен в файле нет.

Проверка при старте, как у `providers.yaml` (ошибка — бэкенд не стартует): YAML читается, есть пресет каждого
формата (`every_rank`, `host`), неизвестных нет, `1 ≤ min ≤ target ≤ max ≤ 40`, числа положительные.

**Смета выпуска** считается на каждый запрос через `Gateway.estimate` маршрутами профиля по умолчанию; слова VO =
`target × words_per_minute`:

| Этап | Запрос |
|---|---|
| `script` | вход `script_input_tokens`, выход `слова × script_output_tokens_per_word` |
| `images` | `shots` отдельных вызовов по одной картинке (округление — на вызов, как в журнале) |
| `voice` | `слова × voice_chars_per_word` символов |

Ответ `FormatPreview`: `channel`, `format`, `preset`, `estimate = {stages: [Cost], usd_micro}` (у каждой строки —
этап, провайдер, `model`, строки единиц), `stale_pricing` — цена хотя бы одной модели сметы сверялась давно.
404 — канала нет (`python -m app.tools.seed`), 422 — неизвестный канал. Смена `default_profile` в
`providers.yaml` или цены в `pricing.yaml` меняет сумму без правок кода.
