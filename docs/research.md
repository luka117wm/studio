# Исследование: идеи и референс

Контракт того, откуда берутся темы выпусков (устав M4, решения 9 и 10). Раздел «Идеи» — M4.8, «Референс» — M4.10.
Радара трендов YouTube нет (нужен ключ YouTube Data API): идеи заводятся руками и приходят из чата через мост
(`docs/bridge.md`). Поэтому у идеи нет «доказательств», «насыщенности» и прочих полей, для которых нет данных.

## Идеи

Код: таблица `ideas` (миграция `007_ideas.sql`), модели `backend/app/models/idea.py`, роутер
`backend/app/api/ideas.py`, разбор ответа чата — `backend/app/pipeline/research/ideas.py`, шаблон промпта —
`backend/app/prompts/ideas.md`. Типы фронта — `@/types/idea`.

### Поля идеи (`Idea`)

| Поле | Тип | Описание |
|---|---|---|
| `id` | `i0001`, `i0002`, … | глобальный номер; выдаётся внутри `BEGIN IMMEDIATE` (L-021) |
| `channel` | `cursus \| otto` | канал; не меняется |
| `title` | str, 1…200 после `strip` | рабочее название; станет названием выпуска |
| `angle` | str | чем подача отличается от очевидной |
| `hook_promise` | str | обещание первых 30 секунд |
| `summary` | str | о чём выпуск, 2–3 предложения |
| `score` | int 0–100 \| `null` | **мнение чата**, а не данные: просмотров и поисковых чисел у чата нет. Так сказано и в промпте |
| `score_reason` | str \| `null` | почему такая оценка, одно предложение |
| `source` | `manual \| bridge` | заведена руками или пришла из чата; не меняется |
| `status` | `proposed \| backlog \| used \| dropped` | ниже |
| `episode_id` | str \| `null` | выпуск, созданный из идеи (`used`) |
| `created_at`, `updated_at` | ISO 8601 UTC | `updated_at` растёт при каждой правке |

Тексты ошибок — одна русская фраза на поле (L-022): «Название не может быть пустым — введите текст.», «Название
длиннее 200 знаков — сократите его.», «Оценка — целое число от 0 до 100 или null.» Оценка `85.0` принимается как 85.

### Статусы

| Статус | Что значит | Куда можно (PATCH) |
|---|---|---|
| `proposed` | предложил чат, в бэклог ещё не взята | `backlog`, `dropped` |
| `backlog` | в бэклоге; заведённая руками идея начинается здесь | `dropped` |
| `dropped` | отброшена; физически идеи не удаляются | `backlog` |
| `used` | взята в выпуск — конечный | никуда |

`used` ставит только создание выпуска из идеи. Неверный переход — **409** с текстом: «Идею со статусом «в бэклоге»
нельзя перевести в «предложена»: можно «отброшена».» Тот же статус — не переход: ничего не меняется.

### Семена ниши

`profile.json → seeds` канала: короткие строки-направления для промпта идей («pirate ships», «Roman legions»).
Живут в профиле, не в коде и не в конфиге.

- `PATCH /api/channels/{id} {seeds}` — только семена; профиль пишется атомарно (temp → rename, L-003).
- Строки после `strip`, пустые выбрасываются; не больше 20, каждая до 80 знаков, без повторов без учёта регистра.
  Нарушение — 422 одной фразой: «Семя «pirates» повторяется — оставьте одно.»
- Пустой список допустим: промпт тогда опирается на формат канала. Пустой список в `profile.json` и в ответе API
  не выгружается — в TS поле `seeds?:` (L-033), обязательным его сделает экран идей.

### Промпт идей

`POST /api/ideas/prompt {channel, count}` (`count` 1…20, по умолчанию 6) → `{text, prompt_id, version, run_id,
count}` и строка журнала моста `task: ideas`, `prompted`. Контекст шаблона `ideas`:

| Ключ | Что |
|---|---|
| `channel_name`, `format` | имя и формат канала; описание обоих форматов — в тексте шаблона |
| `preset_json` | минуты `{min, target, max}`, разделы, слов в минуту — из `config/formats.yaml` |
| `seeds_json` | семена ниши; `[]` — семян нет |
| `avoid_json` | «не повторять»: названия идей бэклога, затем выпусков канала (без «Новый выпуск»), без повторов |
| `count` | сколько идей |

Предложенные (`proposed`) и отброшенные идеи в «не повторять» не входят: первые ещё не решены, вторые можно
предложить заново. Эталон текста — `tests/fixtures/prompts/ideas_cursus.txt`; правка шаблона поднимает `version`.

### Приём ответа

`POST /api/ideas/answer {channel, text}` → `{run_id, created: [Idea], skipped: [{index, title, reason}]}`.

1. `extract_json` (`docs/bridge.md`, «Разбор ответа»); дальше — `{"ideas": [...]}`. Списка нет или он пуст — 422
   `BridgeError` «В ответе нет списка идей: ожидался {"ideas": [...]}.»
2. Каждая идея проверяется отдельно (`IdeaProposal`: `title`, `angle`, `hook_promise`, `summary` обязательны,
   `score` и `score_reason` — нет; лишние ключи чата не мешают). Ошибка одной идеи не роняет остальные: она
   пропускается с причиной («нет поля «angle»»).
3. **Дубль названия** (без регистра и лишних пробелов) — пропуск с пометкой: с идеями канала, кроме `dropped`
   («уже в бэклоге», «уже предложена», «уже взята в выпуск»), с выпусками канала («уже есть выпуск с таким
   названием») и с идеей выше в том же ответе. Повторная вставка того же ответа ничего не удваивает.
4. Принятые сохраняются `proposed`, `source: bridge`, в порядке ответа.
5. Журнал: открытый обмен `ideas` канала закрывается этим ответом, иначе пишется новая строка (как у плана).
   Принята хотя бы одна идея — `applied`, пропуски — в `errors` обмена («идея 3: …», путь `ideas[2]`). Не принята
   ни одна — 422 `BridgeError` «Ни одна идея не принята: 2 пропущены.» с ошибками по идеям, обмен `failed`, в
   `ideas` ничего не пишется.

### API

| Запрос | Ответ |
|---|---|
| `GET /api/ideas?channel=&status=` | `[Idea]`, новые первыми; фильтры необязательны |
| `POST /api/ideas` `IdeaCreate {channel, title, angle, hook_promise, summary, score, score_reason}` | 201 `Idea`: `manual`, сразу `backlog`; 404 — канала нет |
| `PATCH /api/ideas/{id}` `IdeaPatch` | `Idea`; тексты и оценка (`score: null` — сброс), статус по таблице; 409 — переход; 422 — `channel`, `source`, `episode_id`, `id`, даты; 404 — идеи нет |
| `POST /api/ideas/prompt`, `POST /api/ideas/answer` | выше |
| `PATCH /api/channels/{id}` `{seeds}` | `ChannelProfile` |

### Выпуск из идеи

`POST /api/episodes {channel, origin: "backlog", idea_id}` (`docs/episodes.md`), одной транзакцией с созданием:

- идея должна быть этого канала (иначе 422) и в бэклоге (иначе 409: «… взята в выпуск c01 — выпуск создаётся только
  из идеи в бэклоге.»); нет идеи — 404; `idea_id` без `origin: backlog` — 422;
- название выпуска — название идеи, если `title` не прислан явно;
- заявка (`project.json → brief`): `idea` ← название, `angle`, `hook_promise`, `notes` ← `summary`, `idea_id`;
- стадия `idea`; идея → `used`, `episode_id` — выпуск.

Отказ ничего не оставляет: ни каталога, ни строки выпуска, статус идеи прежний.

## Референс

Ролик, чью структуру разбирает чат через мост (устав M4, решение 10). Код: таблица `reference_videos` (миграция
`008_reference_videos.sql`), модели `backend/app/models/reference.py`, роутер `backend/app/api/references.py`,
логика — `backend/app/pipeline/research/` (`subtitles.py`, `reference.py`, `similarity.py`), шаблон промпта —
`backend/app/prompts/reference.md`, настройки — `config/reference.yaml`. Типы фронта — `@/types/reference`.

**Принцип 11.** Текст референса не попадает в промпт плана никогда — ни целиком, ни выдержками. Туда идёт только
структура (`reference_structure`): виды и подписи сегментов (подписи пишет чат своими словами), их длительности,
общий темп, приёмы со счётом и режим. Тест рендерит промпт плана выпуска по референсу и проверяет, что ни одна
5-грамма субтитров фикстуры в нём не встречается. Перед утверждением VO плана сравнивается с текстом референса.
Сеть не используется: ссылка только хранится, субтитры вставляются руками; `yt-dlp` нет.

### Субтитры

`parse_subtitles(text) → [Cue {start, end, text}]`:

| Формат | Как узнаётся | Что вырезается |
|---|---|---|
| SRT | строки `00:01:02,500 --> 00:01:05,000` | номер блока |
| VTT | те же строки с точкой, часы необязательны (`00:04.500`) | `WEBVTT`, заголовки, id реплик, блоки `NOTE` / `STYLE` / `REGION`, теги `<c>`, `<00:00:01.000>`, `<v Имя>`, настройки после времени |
| расшифровка YouTube | таймкод `0:00` / `1:02:03` отдельной строкой или в начале строки | строки без таймкода — к текущей реплике |

Конец без явного значения — начало следующей реплики; у последней — начало плюс время её слов при 150 словах в
минуту (не меньше секунды). Длительность референса — конец последней реплики. Таймкодов нет —
`SubtitlesError` → 422 «Не похоже на субтитры: нет таймкодов. Вставьте SRT, VTT или расшифровку с YouTube.»
Хранится исходный текст как вставлен; реплики разбираются заново при чтении.

### Поля референса (`ReferenceVideo`)

`id` (`ref0001`, внутри `BEGIN IMMEDIATE`), `channel`, `url` (может быть пустым), `title` и `author` (из разбора
чата; до разбора — пусто), `duration_s`, `cues` (сколько реплик), `subtitles`, `analysis` (разбор или `null`),
`metrics` (при разборе, считаются при чтении), `created_at`, `analyzed_at`.

### Разбор через мост

`POST /api/references/{id}/prompt` → `{text, prompt_id, version, run_id}`, строка журнала `task: reference`,
`target_id` — id референса. Контекст: наш канал и пресет (для чего разбор), длительность, реплики `[03:31] text`.
Эталон — `tests/fixtures/prompts/reference_warship.txt` по фикстуре `reference_warship.srt` (текст свой).

`POST /api/references/{id}/answer {text}` → `ReferenceVideo`. Чат возвращает `title`, `author`, `topic` (тема своими
словами одной строкой), `segments[{kind, label, start, facts}]` и `techniques[{text, count}]`. Проверки — все
сразу, ошибки по-русски с номером сегмента (`segments[2].start`):

- `kind` — `hook | promise | rank | retention | finale | other`: «сегмент 2: вид «intro» неизвестен, ожидалось
  одно из: …»;
- `start` — секунды или `mm:ss` / `h:mm:ss`; начало первого — в первые 30 секунд; начала по возрастанию («сегмент
  4: начало 00:30 не позже предыдущего 00:40 — сегменты идут по порядку») и в пределах длительности;
- хотя бы два сегмента; `facts ≥ 0`; у приёма `count ≥ 1`; `topic` непустой.

Ошибка — 422 `BridgeError`, разбор не меняется, обмен `failed`. Принятый разбор заменяет прежний, обмен `applied`.
Лишние ключи чата игнорируются.

### Метрики (`ReferenceMetrics`)

Чистая функция `metrics(cues, analysis, duration_s, norm_wpm)`. Реплика относится к сегменту, в котором
начинается; сегмент длится до начала следующего, последний — до конца ролика.

| Поле | Как считается |
|---|---|
| `segments[]` | длительность, слова, темп (слова в минуту), факты и факты в минуту по сегменту |
| `pace_wpm`, `norm_wpm`, `pace_delta` | слова всех реплик в минуту; темп пресета нашего канала; (темп − норма) / норма |
| `facts_total`, `facts_per_min` | сумма фактов сегментов; на минуту ролика |
| `holds_until_s` | конец последнего сегмента, где плотность фактов не ниже 70 % средней; фактов нет — `null` |
| `retention_hooks_s` | начала сегментов `retention` |
| `segments_total`, `ranks_total` | сегментов всего и из них `rank` |

Средняя длина кадра не считается: нужно видео (решение модуля).

### Выпуск по референсу

`POST /api/references/{id}/episodes {mode}` → 201 `EpisodeListItem`: выпуск канала референса, `origin: reference`,
стадия `script`, название «Новый выпуск» — чужое не переносим. Заявка: `reference_id`, `reference_mode`; идея —
`topic` разбора для `own_version`, пустая для `structure_clone` (тему выбирает пользователь). Разбора нет — 409
«Сначала разберите референс…». Создание — та же транзакция `insert_episode`, что у выпуска из идеи.

Промпт плана (часть 1, `plan_first` v2) получает структуру референса и инструкцию по режиму: `structure_clone` —
новая тема на этой структуре, `own_version` — та же тема своими словами; в обоих — ни одной формулировки референса.

### Сходство

`similarity(plan_vo, reference_text, n, threshold) → Similarity {ratio, threshold, ngram, ok, matched, total,
phrases}`:

- нормализация — нижний регистр, без пунктуации, слова (апостроф внутри слова — часть слова);
- доля — сколько n-грамм VO действующего плана (с повторами, кроме `removed`) встречается среди n-грамм субтитров;
  n-граммы плана — по кадру, через границу кадров не склеиваются; субтитры — одним текстом;
- `ok` — доля не выше порога; `phrases` — до пяти самых длинных совпавших фраз (подряд идущие совпадения склеены);
- `n` и порог — `config/reference.yaml` (`ngram: 5`, `max_similarity: 0.10`), проверка при старте.

`GET /api/projects/{id}/similarity` → `{similarity, reason}`: выпуск не по референсу или плана нет — `similarity:
null` с причиной.

**Утверждение.** Для выпуска с `brief.reference_id` проверка `similarity` в `CHECKS` (`docs/episodes.md`): доля
выше порога — 409 с проблемой плана «Сходство с референсом 18 % при пороге 10 %: перепишите совпавшие фразы —
«…»; «…».» Плана нет — проверки нет.
