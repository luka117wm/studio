# B2A.2 — Опорные портреты облика

**Блок:** B2A — Канон · **Оценка:** 5 ч · **Модель:** Opus · **План до кода:** да

## Цель
Для каждого облика есть лист из шести отобранных вручную опорных кадров, который дальше подаётся референсом в каждый кадр с этим персонажем.

## Что сделать
1. Шесть ракурсов: `front`, `three_quarter`, `profile`, `full_body`, `in_action`, `detail` (руки, обувь, инструмент — то, что чаще всего «уезжает»).
2. Один запуск = одна пачка из шести с общим seed и одинаковым описанием облика; варьируется только строка ракурса. Нейтральный фон и ровный свет: это эталон внешности, а не кадр из ролика.
3. Кандидатов на ракурс — 2–3, пользователь выбирает. Невыбранные уходят в `rejected/`, не удаляются.
4. `chosen.json`: ракурс → файл, seed, версия облика, дата, стоимость.
5. Перегенерация одного ракурса не трогает остальные.
6. Лист привязан к версии облика. Меняется `face` — лист помечается устаревшим и требует пересбора; меняется `clothing` — достаточно перегенерировать `full_body`, `in_action`, `detail`.
7. Копирование облика на новый период: `face`, `build`, `nature` переносятся как есть, `clothing`, `props`, `wear_and_damage` — заново. Это главный механизм «тот же человек в другой эпохе».
8. Оценка стоимости листа показывается до запуска (6 ракурсов × 2 кандидата × цена модели).

## Критерии приёмки
- [ ] генерация листа для `you@powder-monkey-11` даёт 6 ракурсов, каждый с кандидатами
- [ ] выбор записывает `chosen.json`, отбракованные лежат в `rejected/`
- [ ] перегенерация `profile` не меняет остальные пять файлов
- [ ] смена `face` в новой версии облика помечает лист устаревшим
- [ ] копирование облика на другой период сохраняет `face` побайтово (тест)
- [ ] стоимость листа записана в `cost_ledger` с этапом `canon.anchors`

- не удалять отбракованные
- не переиспользовать лист одного облика для другого
