# B0.2 — Контракт director.json

**Блок:** B0 — Фундамент · **Оценка:** 4 ч · **Модель:** Opus · **План до кода:** да (6–10 пунктов + список файлов, ждать «ок»)

## Цель
Есть Pydantic-модель плана съёмки, из неё генерируется JSON Schema и документация, а тестовая фикстура пиратского эпизода проходит валидацию.

## Читать
- `CLAUDE.md` — раздел «Данные: три уровня — три роли» целиком, включая скелет JSON (в нём `canon_ref`, а не блок `canon` — сверить с пунктом 1 ниже перед началом)
- `backend/app/main.py`

## Создать / изменить
- `backend/app/models/director.py` — модели Pydantic v2
- `backend/app/models/validators.py` — доменные проверки и человеческие сообщения
- `docs/director_schema.md` — описание полей, диапазонов, обязательности, примеры
- `backend/app/tools/gen_schema.py` — выгрузка JSON Schema в `docs/director.schema.json`
- `tests/fixtures/director_pirate_10shots.json` — валидная фикстура, 10 кадров, 2 секции
- `tests/fixtures/director_broken_*.json` — 4 невалидные: битый `shot.id`, `motion.strength` вне диапазона, ссылка на несуществующий `section`, пустой `vo`
- `tests/test_director_schema.py`

## Не трогать
- `backend/app/api/` — API появится в B0.3

## Что сделать
1. Модели по скелету из CLAUDE.md: `Director`, `Meta`, `Brief`, `Canon`, `VoiceCfg`, `Section`, `Shot`, `ImageSpec`, `Motion`, `Transition`, `AnimateSpec`, `SfxSpec`, `MusicCue`, `Thumbnail`, `PublishMeta`, `Fact`.
2. Литералы вместо свободных строк: `shot_size`, `motion.type`, `transition.type`, `reference_mode`, `fact.status`.
3. Диапазоны: `motion.strength` 0…0.25, `transition.duration` 0…1.5, `sfx.gain_db` −40…0, `target_minutes` 1…40.
4. Правило частей: при `meta.part > 1` блоки `canon` и `voice` необязательны и игнорируются при импорте.
5. Доменные проверки: уникальность `shot.id`, ссылки `shot.section` существуют, `vo` непустой, `animate.prompt` обязателен при `animate.recommended = true`, `characters` ссылаются на `canon.characters[].id`.
6. Сообщения об ошибках в формате `кадр s047: <что не так>, ожидалось <что>` — русский, без стектрейсов.
7. `gen_schema.py` и первая выгрузка схемы.
8. `docs/director_schema.md`: таблица полей, диапазоны, что обязательно, что необязательно, два примера кадра.
9. Фикстуры: валидная и четыре битые.
10. Тесты: валидная проходит, каждая битая падает с ожидаемым текстом.

## Критерии приёмки
- [ ] `uv run pytest tests/test_director_schema.py -v` зелёный, 5+ тестов
- [ ] `uv run python -m app.tools.gen_schema` обновляет `docs/director.schema.json`
- [ ] каждая битая фикстура даёт сообщение с ID кадра и понятной причиной
- [ ] `docs/director_schema.md` описывает все поля скелета из CLAUDE.md
