**Модуль:** M4 — Идеи, сценарий и план через мост · **Оценка:** 4 ч · **Модель:** Opus · **План до кода:** да

## Цель
Референс сохраняется с текстом субтитров и разбирается через мост: сегменты, приёмы подачи, факты. Метрики и карту
структуры считает код. Выпуск по структуре создаётся с заявкой без текста референса. «Утвердить план» отказывает,
если VO плана слишком похож на референс (принцип 11).

## Что сделать
1. **Субтитры.**
   - Форматы: SRT (`00:01:02,500 --> …`), VTT (`WEBVTT`, теги `<c>` и `<00:00:01.000>` вырезаются), расшифровка
     YouTube — таймкод `0:00` / `1:02:03` отдельной строкой или в начале строки.
   - Результат — `Cue {start, end, text}`; конец без явного значения — начало следующей реплики.
   - Нет ни одного таймкода — ошибка «Не похоже на субтитры: нет таймкодов. Вставьте SRT, VTT или расшифровку с
     YouTube».
   - Длительность референса — конец последней реплики.
2. **Референс** — `id` (`ref0001`), `channel`, `url` (может быть пустым), `title`, `author` (из разбора чата),
   `duration_s`, `subtitles` (исходный текст), `analysis` (JSON или `null`), `created_at`, `analyzed_at`.
3. **Промпт разбора.**
   - Контекст: реплики с таймкодами компактно (`[03:31] text`), длительность, формат нашего канала (для чего
     разбор).
   - Чат возвращает: `title`, `author`, `topic` — тема своими словами, одной строкой; `segments[]` — `kind` (`hook
     | promise | rank | retention | finale | other`), `label`, `start` (секунды или `mm:ss`), `facts` (сколько
     фактов в сегменте); `techniques[]` — `text`, `count`.
   - Проверка: сегменты по возрастанию, начало первого ≤ 30 с, начала в пределах длительности, хотя бы два
     сегмента, `count ≥ 1`. Ошибки — по-русски, с номером сегмента.
4. **Метрики** — чистая функция:
   - длительности сегментов;
   - темп — слова реплик в минуту, общий и по сегментам;
   - плотность фактов в минуту;
   - до какой минуты плотность держится — последний сегмент, где она не ниже 70 % средней;
   - крючки удержания (время начала);
   - сколько сегментов и сколько из них `rank`;
   - сравнение темпа с нормой канала из `formats.yaml` (`words_per_minute` пресета).

   Средняя длина кадра не считается: нужно видео (решение модуля).
5. **Сходство.**
   - Текст нормализуется: нижний регистр, без пунктуации, слова.
   - Доля n-грамм VO действующего плана, которые встречаются в субтитрах; `n` и порог — из `config/reference.yaml`.
   - В ответе — доля, порог, `ok` и до пяти самых длинных совпавших фраз.
   - Плана нет — `null` с причиной.
6. **Выпуск по референсу** — `POST /api/references/{id}/episodes`:
   - выпуск канала референса, `origin: reference`, заявка с `reference_id` и `reference_mode`;
   - для `own_version` идея = `topic` разбора, для `structure_clone` идея пустая — тему выбирает пользователь;
   - название — «Новый выпуск». Чужое название не переносим.
   - Разбора ещё нет — 409 «Сначала разберите референс».
7. **Промпт плана с референсом** получает только сегменты (вид, подпись, длительность), общий темп и приёмы — с
   инструкцией по режиму. Тест: ни одна 5-грамма субтитров фикстуры не встречается в отрендеренном промпте.
8. **Утверждение.** Для выпуска с `reference_id` сходство выше порога даёт проблему «Сходство с референсом 14 % при
   пороге 10 %: перепишите совпавшие фразы» со списком фраз; плана нет — проверка не нужна.

## Критерии приёмки
- [ ] субтитры: SRT, VTT с тегами, расшифровка YouTube в обоих видах, текст без таймкодов — ошибка
- [ ] разбор: ответ с прозой → сохранён; сегменты не по порядку и неизвестный `kind` — ошибки с номером
- [ ] метрики на фикстуре совпадают с посчитанными в тесте вручную
- [ ] сходство: план из своих фраз — ниже порога; план с вставленными фразами субтитров — выше, совпадения
      перечислены
- [ ] выпуск по референсу: заявка с `reference_mode`; промпт плана без 5-грамм субтитров; утверждение отказывает
      при сходстве выше порога
- [ ] `uv run pytest && uv run ruff check . && uv run mypy backend tests`; `typegen:check`
