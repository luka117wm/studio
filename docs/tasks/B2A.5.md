# B2A.5 — Проверка консистентности

**Блок:** B2A — Канон · **Оценка:** 2 ч · **Модель:** Sonnet · **План до кода:** нет

## Цель
После пачки кадров сразу видно, где персонаж перестал быть собой и где в эпоху пролезло лишнее.

## Читать
- `backend/app/pipeline/canon/anchors.py`
- `backend/app/models/project.py`
- `CLAUDE.md` — принцип 12 (очередь GPU)

## Создать / изменить
- `backend/app/pipeline/canon/consistency.py` — кроп лица, эмбеддинг, сравнение с опорным фасом
- `backend/app/pipeline/canon/anachronism.py` — проверка по списку `forbidden` через дешёвую VLM
- `frontend/src/screens/generate/ConsistencyGrid.tsx`
- `tests/test_consistency.py`

## Не трогать
- `backend/app/pipeline/images/prompt_builder.py`

## Что сделать
1. Детекция и кроп лица локально, эмбеддинг, косинусное сходство с опорным фасом облика. Порог в конфиге, по умолчанию мягкий: задача — поднять подозрительные наверх, а не блокировать.
2. Кадры ниже порога помечаются `consistency_low` в project.json.
3. Сетка кропов по всему эпизоду, отсортированная по возрастанию сходства: первые 10 — то, что смотрит человек.
4. Анахронизмы: один дешёвый VLM-запрос на кадр со списком `forbidden` периода, ответ строго `{"found": [...]}`. Пометка `anachronism_suspect`, не блокировка.
5. Проверки идут в GPU-очереди и ставятся на паузу во время рендера.
6. Стоимость VLM-проверки учитывается в ledger этапом `canon.check`, и её можно выключить в настройках.

## Критерии приёмки
- [ ] на фикстуре из 20 кадров подсунутый чужой персонаж попадает в первую тройку по сортировке
- [ ] кадр со списком `forbidden`, содержащим явный предмет, помечается `anachronism_suspect`
- [ ] проверки не запускаются во время рендера
- [ ] выключение проверки в настройках убирает и расходы, и пометки

## Команды проверки
```bash
uv run pytest tests/test_consistency.py -v
```

## Чего не делать
- не блокировать публикацию по этим пометкам: это подсказка человеку, а не цензор
- не гонять тяжёлую модель: проверка должна быть дешевле кадра
