# B0.6 — Типы из Pydantic (typegen)

**Блок:** B0 — Фундамент · **Оценка:** 1 ч · **Модель:** Sonnet · **План до кода:** нет

> Токенная часть этого этапа (цвета, типографика, шрифты локально) выполнена в **M1.1** — `frontend/src/styles/`,
> `pnpm -C frontend tokens:check`. Здесь остался только typegen. Зависит от B0.2 (`backend/app/tools/gen_schema.py`).

## Цель
TS-типы фронта генерируются из Pydantic-моделей бэкенда одной командой, и CI-проверка ловит устаревшие типы.

## Читать
- `backend/app/tools/gen_schema.py` (из B0.2)
- `docs/director.schema.json`
- `frontend/package.json` — раздел `scripts`

## Создать / изменить
- `frontend/scripts/typegen.mjs` — JSON Schema → TS через json-schema-to-typescript
- `frontend/src/types/` — только генерируемое, с шапкой «сгенерировано, не править»
- `frontend/package.json` — скрипт `typegen` и `typegen:check`

## Не трогать
- ничего в `backend/`, кроме вызова `gen_schema`
- `frontend/src/styles/` — токены закрыты в M1.1

## Что сделать
1. Скрипт: вызвать `uv run python -m app.tools.gen_schema`, сконвертировать схему в TS, положить в `src/types/director.ts` (и `project.ts`, когда появится B0.3).
2. Шапка в каждом сгенерированном файле: «сгенерировано, не править» и команда регенерации.
3. `typegen:check`: после генерации `git status --porcelain frontend/src/types/` пуст — иначе код 1 с подсказкой.
4. Тест в vitest: `src/types/` не содержит ручных правок (тот же приём, что `tokens:check`).

## Критерии приёмки
- [ ] `pnpm -C frontend typegen` не меняет git-статус на свежем коде
- [ ] `pnpm -C frontend typegen:check` падает, если модель Pydantic изменилась, а типы — нет
- [ ] `import type { Director } from '@/types/director'` компилируется в strict

## Команды проверки
```bash
pnpm -C frontend typegen && git status --porcelain frontend/src/types/
pnpm -C frontend typegen:check
```

## Чего не делать
- не править файлы в `src/types/` руками
- не описывать типы контракта вручную «пока схемы нет» — ждать B0.2
