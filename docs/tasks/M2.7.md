# M2.7 — Typegen и API-клиент фронта

**Модуль:** M2 — Бэкенд-фундамент · **Оценка:** 2 ч · **Модель:** Sonnet · **План до кода:** нет

## Цель
TS-типы фронта генерируются из Pydantic-моделей одной командой, проверка ловит устаревшие типы, во фронте есть
типизированный клиент `/api` и обёртка SSE — без единого запроса из экранов (это M3).

## Читать
- `backend/app/tools/gen_schema.py`, `docs/director.schema.json`
- `backend/app/models/{director,project,channel}.py`, `backend/app/api/{episodes,jobs,cost}.py` — какие модели отдаёт API
- `frontend/package.json` (scripts), `frontend/scripts/sync-tokens.mjs` — образец `--check`
- `frontend/src/types/fixtures.ts` — что заменяется в M3

Больше ничего не открывать. Нужен файл вне списка — сначала сказать.

## Создать / изменить
- `backend/app/tools/gen_schema.py` — выгрузка схем всех API-моделей в `docs/schema/*.schema.json`
  (director остаётся в `docs/director.schema.json`)
- `frontend/scripts/typegen.mjs` — JSON Schema → TS (`json-schema-to-typescript`), шапка «сгенерировано, не править»,
  режим `--check`
- `frontend/src/types/{director,project,channel,episode,job,cost}.ts` — только генерируемое
- `frontend/src/api/client.ts` — `api.get/post/patch` с типами ответов, ошибки как `{status, message}` для UI
- `frontend/src/api/sse.ts` — `subscribe(onEvent)` на `EventSource('/api/events')` с переподключением и `Last-Event-ID`
- `frontend/package.json` — `typegen`, `typegen:check`, devDependency `json-schema-to-typescript`
- `frontend/src/api/__tests__/client.test.ts`, `sse.test.ts`; тест «`src/types/` без ручных правок» (приём `tokens:check`)

## Не трогать
- `frontend/src/types/fixtures.ts` и `mocks/fixtures.ts` — уходят в M3 вместе с экранами
- `frontend/src/ui/**`, `frontend/src/app/**`, `frontend/src/styles/**`

## Что сделать
1. `gen_schema.py`: детерминированный вывод, стабильный порядок ключей, `$id` на модель.
2. `typegen.mjs`: вызывает `uv run python -m app.tools.gen_schema`, конвертирует, пишет файлы с шапкой и командой
   регенерации; `--check` — после генерации `git status --porcelain frontend/src/types/` пуст, иначе код 1 с подсказкой.
3. `client.ts`: `fetch` только к `/api`, JSON, таймаут, ошибки в человеческом виде (что случилось и что сделать —
   текст приходит с бэкенда, клиент не сочиняет); без провайдеров и очередей во фронте.
4. `sse.ts`: `EventSource`, переподключение с задержкой, разбор типов событий из M2.5, отписка.
5. Тесты с замоканным `fetch` и `EventSource`; тест на ручные правки в `src/types/`.
6. `pnpm typegen:check` в `CLAUDE.md` уже упомянут — сверить команды.

## Критерии приёмки
- [ ] `pnpm -C frontend typegen` не меняет git-статус на свежем коде
- [ ] `pnpm -C frontend typegen:check` падает, если модель Pydantic изменилась, а типы — нет (проверить руками, не коммитить)
- [ ] `import type { Director } from '@/types/director'` компилируется в strict; `tsc -b` чист
- [ ] `pnpm -C frontend test --run` зелёный, e2e-эталоны не изменились

## Команды проверки
```bash
pnpm -C frontend typegen && git status --porcelain frontend/src/types/
pnpm -C frontend typegen:check && pnpm -C frontend test --run && pnpm -C frontend e2e
```

## Чего не делать
- не править `src/types/` руками; не подключать экраны к API (M3)
- не менять оболочку и кит — тег `m1`
