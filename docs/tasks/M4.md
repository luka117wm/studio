# M4 — Идеи, сценарий и план через мост

Четвёртый модуль. Составлен 2026-10-02 по `STATUS.md` (разделы 26–28, «Дальше»), артбордам
`design/Studio - 2 Идеи.dc.html` и `design/Studio - 3 Сценарий и план.dc.html` и решениям пользователя при
составлении:
- ключа Anthropic нет, поэтому с Claude работаем только через мост;
- идеи — бэклог и идеи из чата, радар YouTube откладывается;
- референс делается полностью, как в артборде;
- переключатель «Claude API» виден, но выключен;
- правки — по полям кадра, JSON сохраняется новой версией;
- всё это — один модуль.

Оценка: 44 часа, двенадцать этапов. Ветка `m4-script-bridge` от `main` после слияния PR #3 (пока PR открыт — от
`handoff-fixes`), тег `m4` на выходе.

**Что на выходе.** Выпуск проходит путь «идея → заявка → план частями из чата → правки → смета → утверждение» без
единого вызова Anthropic API.
- **Мост через чат.** Приложение собирает промпт, пользователь копирует его в claude.ai и вставляет ответ обратно.
  Бэкенд достаёт из ответа JSON, проверяет и применяет. Задачи моста:
  - план — `director.json` частями по 26 кадров;
  - идеи;
  - разбор референса.
- **Экран 3 «Сценарий и план»:**
  - заявка выпуска и панель моста по частям;
  - три режима: «Сценарий» (лист 760), «План кадров» (таблица), «JSON» (редактор с проверкой);
  - правки кадров с автосохранением;
  - факт-чек, смета и кнопка «Утвердить план».
- **Экран 2 «Идеи»:**
  - вкладка «Тренды» — семена ниши, бэклог, идеи из чата («В бэклог», «Начать выпуск»);
  - вкладка «Референс» — субтитры → разбор через мост → карта структуры, метрики, приёмы подачи, сходство →
    «Новая тема по этой структуре» / «Своя версия этой темы».
- **Диалог «Новый выпуск».** «Из бэклога идей» включён; «Из референса» ведёт на вкладку «Референс».
- **Бэкенд:**
  - журнал обменов моста;
  - заявка и правки кадров в `project.json`, версии плана из JSON;
  - смета плана через gateway;
  - утверждение со сменой стадии на `generate`;
  - проверка сходства с референсом (принцип 11).

**Чего на выходе нет и не должно быть.**
- **Вызовов Anthropic API.** Сегмент «Claude API» виден и выключен, в подсказке — про ключ. Когда ключ появится,
  API подключается отдельной сессией на тех же промптах (строка в `docs/roadmap.md`). Туда же — кэш ответов LLM и
  учёт того, что у Opus 5.5 мышление не отключается.
- **Автоматизации чата.** Приложение не открывает claude.ai, само не читает буфер обмена и не обращается к подписке из
  кода (`CLAUDE.md`, «Чего не делать»). Копирование — по клику, вставка — руками.
- **Радара трендов YouTube**, выбросов и блока «Доказательства» у идей. Это отдельный модуль, нужен ключ YouTube Data
  API. До него в центре вкладки «Тренды» — бэклог.
- **Загрузки субтитров по ссылке** и метрики «Средняя длина кадра» у референса. Ссылка хранится, текст вставляется
  вручную; для длины кадра нужно видео.
- **Действий по выделению текста** («Переписать», «Проверить факт», «Разбить кадр здесь») — после API.
- **Миниатюр кадров** на листе и в таблице: до M6 — плейсхолдеры.
- **Генерации.** «Утвердить план» ставит стадию `generate`; очередь кадров — M6.
- **Канона.** Id эпох и обликов в плане — заготовки; файлы канона создаст модуль канона.

## Решения модуля

Приняты при составлении, чтобы этапы не спорили о них заново.

1. **Мост — единственный путь к Claude в M4.**
   - **Задача моста** — это промпт из шаблона `backend/app/prompts/<id>.md` плюс контекст, который собирает код.
     У шаблона front-matter: `id`, `version`, `task`, `model_hint`; текст — на английском. Пользователь копирует
     промпт, чат отвечает, ответ вставляется в приложение.
   - **Разбор ответа.** Бэкенд достаёт из ответа ровно один JSON: блок ```json или первый сбалансированный объект,
     проза вокруг допустима. Затем проверяет его схемой задачи и применяет. Ошибки — по-русски, с id кадра и
     подсказкой, что попросить у чата.
   - **Журнал.** Каждый обмен — строка `bridge_runs`: задача, выпуск или референс, версия и хэш промпта, часть,
     статус, ошибки, время. Отсюда берутся «Последний прогон» и состояние частей.
   - **API-этап возьмёт те же шаблоны:** промпт не знает, как его доставят.
   - **Деньги.** Для приложения мост бесплатен: строк в `cost_ledger` нет, в смете строка плана — «мост через чат,
     $0».
2. **Источник плана задаёт `config/providers.yaml → plan_source: bridge`** (`bridge | api`). Без
   `ANTHROPIC_API_KEY` вариант `api` недоступен, и переключатель на экране 3 это показывает. При `bridge` смета
   пресета в диалоге M3 не включает строку сценария.
3. **План приходит частями.**
   - Число частей: `parts_total = ceil(кадры пресета / plan.shots_per_part)`; размер части — в
     `config/formats.yaml`, 26 кадров, как в артборде.
   - Часть 1 — полный документ. Часть k — продолжение с кратким конспектом уже принятых частей (разделы, последний
     id кадра), чтобы продолжить мог и новый чат.
   - Сборка, проверка целиком и импорт — механизм M2.4. Контракт `director.json` не меняется, кроме
     необязательного `facts[].shot_id` (решение 12).
4. **`canon_ref` и `voice` подставляет код, а не чат** (принцип 13).
   - Чат пишет в кадрах только id эпох (`caribbean-1716`) и обликов (`you@powder-monkey-11`) — по правилам формата.
   - Перед проверкой код строит `canon_ref` из ссылок кадров: `style/v001`, `periods/<id>/v001`,
     `characters/<персонаж>/v001#<облик>`. До модуля канона это заготовки: файлов ещё нет, модуль канона создаст их по
     этим id.
   - `voice` берётся из профиля канала, там появляется поле `voice` (`voice_id`, `pace_wpm`). Модель — маршрут
     `voice` в `providers.yaml`. Пока голос не выбран — `voice_id: "unset"`, выбор — в модуле голоса.
5. **Заявка выпуска — `project.json → brief`:** идея, угол, обещание хука, заметки, источники, `idea_id`,
   `reference_id`, `reference_mode`. Заполняется на экране 3 либо из идеи или референса и уходит в промпт плана.
   `director.brief` — то, что вернул чат.
6. **Правки плана.**
   - **«Сценарий» и «План кадров».** Правка поля кадра пишется в `project.json → shots[id].user_override` через
     автосохранение M3 (дебаунс 800 мс). Типизированный `ProjectPatch` закрывает хвост M2/M3. Импорт новой версии
     правку не затирает; конфликт — `stale` с причиной (правило M2.4).
   - **Действующий план** — это версия плюс правки. Его считает одна чистая функция бэкенда, фронт получает готовый.
   - **«JSON».** План правится целиком с живой проверкой и сохраняется новой версией `vNNN` через тот же импорт. В
     индексе версий — источник: `source: bridge | manual | api`.
7. **Стадии.**
   - Создание из бэклога — `idea` (как в M3).
   - Первый импорт плана — `script`.
   - «Утвердить план» — `generate` и `project.json → approved_version` (принцип 10).
   - Новая версия после утверждения возвращает стадию в `script` — утвердить нужно снова. M6 генерирует только
     утверждённую версию.
8. **Утверждение проверяет:**
   - план собран и валиден, у каждого кадра есть VO и промпт;
   - для выпуска из референса — сходство VO с текстом референса ниже порога (принцип 11).

   Смета показывается до клика вместе с остатком месячного бюджета. Превышение бюджета здесь — предупреждение;
   отказ даёт очередь генерации в M6 (принцип 6).
9. **Идеи.**
   - Таблица `ideas`: канал, название, угол, обещание хука, кратко, оценка чата 0–100 с причиной, источник
     `manual | bridge`, статус `proposed | backlog | used | dropped`. `proposed` — идею предложил чат,
     в бэклог она ещё не взята.
   - Семена ниши — `profile.json → seeds` канала.
   - Промпт идей получает формат, семена, бэклог и названия выпусков канала — чтобы идеи не повторялись.
   - «Начать выпуск» — `POST /api/episodes {origin: backlog, idea_id}`: заявка заполняется из идеи, идея получает
     статус `used`.
10. **Референс.**
    - **Хранение.** Таблица `reference_videos` (`references` — зарезервированное слово SQL): канал, ссылка,
      название и автор, длительность, текст субтитров с таймкодами, разбор. Субтитры вставляются руками — SRT, VTT
      или расшифровка YouTube с таймкодами; разбирает их код.
    - **Разбор через мост.** Чат возвращает сегменты (хук, обещание, ранг, крючок удержания, финал) с началом,
      приёмы подачи со счётом и факты по сегментам.
    - **Метрики считает код:** длительности сегментов, темп в словах в минуту, плотность фактов в минуту, крючки
      удержания. Норма канала для сравнения — из `formats.yaml`.
    - **Сходство** — по n-граммам слов: VO действующего плана против текста референса. `n` и порог — в
      `config/reference.yaml` (в артборде порог 10 %).
    - **Выпуск по референсу.** «Новая тема по этой структуре» и «Своя версия этой темы» создают выпуск с
      `origin: reference` и `reference_mode: structure_clone | own_version`. В промпт плана уходят только сегменты,
      длительности, темп и приёмы, но не текст референса (принцип 11).
11. **Фронт — как в M3.**
    - Данные — TanStack Query, правки — автосохранение `app/autosave.ts`.
    - Моки `mocks/api.ts` пополняются ответами новых путей, e2e идёт на моках.
    - Вкладки экрана 3 — ⌘⇧1…⌘⇧3 (`layout.md`), переключатель вида — SegmentedControl в заголовке.
    - Эталоны экранов 2, 3 и диалога переснимаются один раз — в M4.12.
12. **Контракты.**
    - Новые документы: `docs/bridge.md` (M4.1) и `docs/research.md` — идеи и референс (M4.8).
    - Правки: `docs/project_schema.md`, `docs/director_schema.md` (источник версии и необязательный
      `facts[].shot_id` — факт-чек ссылается на кадр, как в артборде), `docs/episodes.md` (стадии),
      `docs/providers.md` (`plan_source`).
    - Новые документы — строками в карте `CLAUDE.md`.

## Что идёт следом

- **Модуль канона** (черновики `B2A.*`) — по id эпох и обликов из планов M4 (заготовки `v001`) создаёт стиль, эпохи
  и облики, опорные портреты и сборщик промпта.
- **Claude API** — одна сессия, когда появится ключ.
- **Радар трендов YouTube** — отдельным модулем, когда будет ключ YouTube Data API.
