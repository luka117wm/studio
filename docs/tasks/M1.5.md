# M1.5 — Каталог состояний

**Модуль:** M1 — Оболочка · **Оценка:** 3 ч · **Модель:** Sonnet · **План до кода:** нет

## Цель
Экран 10 — работающий каталог: каждый компонент кита показан во всех состояниях, каждое состояние приложения (пусто, загрузка, ошибка, отказ по бюджету, нет сети) представлено карточкой.

## Читать
- `design/Studio - 10 Состояния.dc.html` — что именно должно быть на экране
- `design/CLAUDE.md` — правила состояний
- `frontend/src/ui/index.ts`
- `frontend/src/app/keyboard.ts`

## Создать / изменить
- `frontend/src/screens/states/` — экран каталога, секции по группам компонентов
- `frontend/src/screens/states/registry.ts` — реестр демонстраций
- `frontend/src/screens/states/__tests__/coverage.test.ts`

## Не трогать
- `frontend/src/ui/**` — кит закрыт; нашёл дефект — записать список, не править здесь

## Что сделать
1. Каталог строится из реестра: компонент → набор демонстраций (название состояния + узел). Добавление компонента в кит без записи в реестр должно ронять тест покрытия.
2. Группы: управление, ввод, слои (диалоги, поповеры, меню), обратная связь (прогресс, тосты, скелетоны), пустые состояния, состояния ошибок.
3. Отдельная секция — состояния продуктовые, а не компонентные: нет выпусков, нет идей, план не импортирован, генерация с ошибкой кадра, отказ по бюджету («месячный лимит $150 исчерпан»), нет сети, долгая операция с возможностью отмены. Тексты брать из макета.
4. Секция клавиатуры: список сочетаний из реестра M1.4.
5. Тест покрытия: каждый экспорт из `src/ui` встречается в реестре хотя бы раз.
6. Каталог доступен только в dev-сборке; в production-сборке маршрут отсутствует.
7. По ходу работы вести список расхождений с макетом и дефектов кита — он понадобится на M1.6.

## Критерии приёмки
- [ ] тест покрытия падает, если добавить компонент в `src/ui` и не внести в реестр
- [ ] на экране присутствуют все группы, включая продуктовые состояния и клавиатуру
- [ ] маршрут отсутствует в production-сборке (проверить `pnpm build && pnpm preview`)
- [ ] список расхождений с макетом составлен

## Команды проверки
```bash
pnpm -C frontend test --run
pnpm -C frontend build && pnpm -C frontend preview
```

## Чего не делать
- не чинить кит из каталога: дефекты копятся списком и правятся отдельной сессией
- не добавлять состояния, которых нет в макете
