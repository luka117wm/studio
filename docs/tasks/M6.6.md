## Цель
Новая версия кадра проверяется дешёвой VLM по списку `forbidden` своей эпохи: найденное помечается
`anachronism_suspect` со списком предметов, расход виден в журнале, а выключенная в профиле канала проверка не
платит и не пишет пометок.

## Что сделать
1. **Этап `check`** — отдельный маршрут, а не `images`: другая цена и другой вид вызова. Модель — только в
   `config/providers.yaml` (принцип 5), цена — в `pricing.yaml`; без цены бэкенд не стартует.
2. **Запрос.** Картинка выбранной версии (миниатюра 320 — дешевле и достаточно для предметов) и список `forbidden`
   эпохи кадра. Шаблон просит назвать только предметы из списка, которые видны в кадре, ответ строго
   `{"found": ["..."]}`.
3. **Разбор** — ровно один JSON с ключом `found` (список строк). Мусор вокруг или другая форма — проверка
   `failed` с текстом, кадр не помечается. Найденное, которого нет в `forbidden` (по `rapidfuzz` с порогом), —
   отбрасывается: VLM не придумывает новые запреты (L-036: проверять кодом, а не надеждой на промпт).
4. **Пометка** — `checks.anachronism`: `{status: ok | suspect | failed | off, found: [...]}` у версии. `suspect` —
   непустой `found`. Ничего не блокирует.
5. **Деньги.** Оценка — по токенам картинки и списка; бюджет выпуска до постановки входит в оценку `shot_image`
   (одна сумма на кадр). Строка `cost_ledger` — этап `check`, кадр, джоб. Кэш по хэшу входов (картинка + список +
   модель): перепроверка той же версии не платит.
6. **Выключатель** — `profile.json → checks.anachronism`. Выключено — вызова нет, оценка без него, статус `off`.
   Включение обратно не перепроверяет старые версии само: для этого `POST …/shots/{id}/check` (M6.5).
7. **Тесты** — фейковый транспорт: найден запрещённый предмет — `suspect`; найдено чужое — отброшено; битый ответ —
   `failed`; выключено — ни вызова, ни строки журнала. Живой тест — один запрос к настоящей модели, центы.

## Критерии приёмки
- [ ] `uv run pytest tests/test_anachronism_check.py tests/test_providers.py -v` зелёные
- [ ] выключатель: после `PATCH` профиля `checks.anachronism=false` новая версия — `off`, строк `check` в журнале нет
- [ ] `uv run pytest -m live -k vision_check -v -rP` (вручную, согласие пользователя, меньше цента): картинка с явным
      предметом из списка — он в `found`
- [ ] бэкенд стартует с новым этапом: цена модели есть, `checked_at` свежий

## Чего не делать
- не блокировать кадр по `suspect`
- не добавлять найденное в `forbidden` эпохи автоматически: канон правит человек
- не гонять тяжёлую модель: проверка должна быть дешевле кадра в десятки раз
