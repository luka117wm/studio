# M1.2 — UI-кит: примитивы

**Модуль:** M1 — Оболочка · **Оценка:** 5 ч · **Модель:** Sonnet · **План до кода:** нет

## Цель
Все примитивы из `components.md` существуют, типизированы, покрыты состояниями и не содержат ни одного цвета мимо токенов.

## Читать
- `design/handoff/components.md` — целиком, это спецификация
- `design/CLAUDE.md` — правила состояний
- `frontend/src/styles/theme.css`

## Создать / изменить
- `frontend/src/ui/` — по файлу на компонент, плюс `index.ts` с реэкспортом
- `frontend/src/ui/cn.ts` — склейка классов на clsx
- `frontend/src/ui/__tests__/` — тесты на состояния и доступность

## Не трогать
- `frontend/src/styles/**` — токены закрыты в M1.1
- `design/**`

## Что сделать
1. Инвентарь строго по `components.md`. Если компонента там нет — он не нужен на этом этапе. Если есть, но непонятен — спросить, а не придумать.
2. Ожидаемый набор: Button (варианты primary/secondary/ghost/danger, размеры, loading, disabled, с иконкой), IconButton, Input, Textarea, Select, Chip (в том числе удаляемый), Badge, StatusDot, Toggle, Slider, NumberField, Tooltip, Popover, DropdownMenu, Dialog, Tabs, ProgressBar, Toast, EmptyState, Skeleton, Divider, ScrollArea, KeyHint. Точный список и пропсы — из `components.md`, этот перечень только для оценки объёма.
3. Каждый компонент: все состояния из спецификации, включая hover, focus-visible, active, disabled, loading, error. Состояние, которого нет в макете, не выдумывать.
4. Пропсы минимальные и честные: без `any`, без `style`, без «пробрасываем всё вниз». Варианты — union-типы, не строки.
5. Доступность: Dialog с ловушкой фокуса и возвратом, Popover и Menu с закрытием по Escape и клику вне, Tooltip не по hover-only (должен открываться и по фокусу), у всех интерактивных элементов доступные имена.
6. Латунный акцент — ограниченный ресурс: primary-кнопка на экране одна. Если в компоненте есть соблазн сделать вторую акцентную — это secondary.
7. Тесты: рендер каждого варианта, клавиатурное поведение диалога и меню, отсутствие hex в исходниках кита.

## Критерии приёмки
- [ ] каждый компонент из `components.md` существует и экспортируется из `src/ui`
- [ ] `pnpm -C frontend test` зелёный
- [ ] `pnpm -C frontend lint` без ошибок, `any` в `src/ui` отсутствует
- [ ] Dialog: Tab не выходит за пределы, Escape закрывает, фокус возвращается на триггер
- [ ] в `src/ui` нет ни одного hex

## Команды проверки
```bash
pnpm -C frontend test --run
pnpm -C frontend lint
grep -rEn "#[0-9a-fA-F]{3,8}\b" frontend/src/ui && echo "НАЙДЕН HEX" || echo ok
```

## Чего не делать
- не тащить UI-библиотеки (radix, shadcn, headless-ui): кит делается по своему макету
- не создавать компоненты «про запас»
- не решать вопросы раскладки: это M1.3
