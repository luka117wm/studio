# M2 — Бэкенд-фундамент

Второй модуль. Составлен 2026-09-19 по `STATUS.md` (итоги M1) из черновиков `docs/drafts/B0.1`–`B0.6`. Оценка: 20–24 часа,
семь этапов, семь сессий. Ветка `m2-backend`, тег `m2` на выходе.

**Почему раньше экранов.** Порядок из `handoff/stack.md` ставит вторым «Выпуски и календарь слотов», но третьим идёт
«Сценарий и план» с мостом через чат и валидацией JSON — а валидировать нечем без контракта. Дешевле положить
фундамент сразу после оболочки, чем писать валидацию и хранилище дважды.

**Что на выходе.** Бэкенд, на который можно опереться всеми следующими модулями: Pydantic-контракт `director.json`
с JSON Schema и документацией; хранилище выпусков на диске с атомарной записью и SQLite с миграциями; импорт версий плана
с мёрджем по `shot.id`, `stale` и защитой ручных правок; очередь джобов, переживающая перезапуск, с прогрессом по SSE и
отменой; единый слой провайдеров с ценой до клика, журналом расходов и бюджетами; ключи провайдеров проверены живым
тестом; TS-типы фронта генерируются из Pydantic одной командой, есть типизированный клиент `/api` и обёртка SSE.

**Чего на выходе нет и не должно быть.** Настоящих вызовов моделей в пайплайне (только проверка ключей под
`pytest -m live`), экранов поверх API (фронт по-прежнему на фикстурах — они уступают место данным в M3), компоновщика,
голоса, канона. Хвосты M0 закрываются здесь первым этапом, чтобы дальше не спотыкаться о `uv init`.

## Ключи провайдеров

Нужны только в **M2.6** для `uv run pytest -m live` (несколько центов): Anthropic, Gemini, ElevenLabs. Kling и YouTube
OAuth — в своих модулях (M8, M10). Где взять и куда положить — `docs/api_keys.md`. До M2.6 ключи не нужны: все тесты
идут на фейковом провайдере, сеть замокана.

## Приёмка M2 целиком

Перед `git tag m2`:

- [ ] семь этапов закрыты, коммит на каждый
- [ ] `uv run pytest && uv run ruff check . && uv run mypy backend` — всё зелёное, `pytest -m live` проходит с ключами
      (или каждый пропуск объяснён в `STATUS.md`)
- [ ] `pnpm -C frontend test && lint && build && e2e && typegen:check` — зелёное; оболочка M1 не изменилась
      (эталоны e2e не переснимались)
- [ ] `./run.sh` поднимает оба процесса; `GET /api/health`, `GET /api/channels`, `GET /api/events` отвечают
- [ ] `tests/fixtures/director_pirate_10shots.json` валиден, каждая битая фикстура даёт сообщение с ID кадра
- [ ] прерванная запись 500 раз не портит файл; `kill -9` во время пачки джобов — после рестарта пачка доходит, дублей нет
- [ ] превышение бюджета — 409 с текстом, джоб не поставлен; повторный вызов с теми же входами — `cached`, $0
- [ ] `docs/director_schema.md`, `docs/director.schema.json`, `docs/providers.md`, `config/providers.yaml`,
      `config/pricing.yaml` существуют и описаны в карте `CLAUDE.md`
- [ ] в git нет ни одного секрета (`git log -p | grep -i api_key` пуст), `backend/.env` в `.gitignore`
- [ ] `STATUS.md` обновлён: «Сделано» пополнен, «Дальше» начинается с модуля M3
- [ ] `docs/LESSONS.md` пополнен, если были грабли (SQLite под asyncio, SSE за прокси Vite — вероятные кандидаты)
