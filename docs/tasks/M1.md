# M1 — Оболочка, токены, UI-кит, каталог состояний

Первый модуль из порядка реализации в `design/handoff/stack.md`. Оценка: 16–20 часов, шесть этапов, шесть сессий. Ветка `m1-shell`, тег `m1` на выходе.

**Что на выходе.** Приложение открывается, выглядит как артборды, по нему можно ходить между всеми двенадцатью экранами (пустыми, кроме оболочки), все компоненты UI существуют во всех состояниях и показаны на экране 10, клавиатура работает, скриншоты Playwright совпадают с макетами по раскладке.

**Чего на выходе нет и не должно быть.** Бэкенда, запросов, реальных данных, таймлайна, canvas-превью, генерации. Всё содержимое экранов — из файла фикстур. Это принципиально: оболочка и кит, сделанные поверх настоящих данных, всегда получаются кривыми, потому что подстраиваются под первый попавшийся ответ API.

## Приёмка M1 целиком

Перед `git tag m1`:

- [ ] шесть этапов закрыты, коммит на каждый
- [ ] `pnpm -C frontend test && pnpm -C frontend lint && pnpm -C frontend build && pnpm -C frontend e2e` — всё зелёное
- [ ] hex вне `tokens.css` отсутствует
- [ ] каталог состояний покрывает весь кит, тест покрытия работает
- [ ] `docs/visual_review.md` заполнен, незакрытых расхождений нет
- [ ] `STATUS.md` обновлён: «Сделано» пополнен, «Дальше» начинается с модуля M2
- [ ] `docs/LESSONS.md` пополнен, если были грабли (Tailwind v4 и фокус в диалогах — вероятные кандидаты)
- [ ] ни одного сетевого запроса при загрузке приложения

## Что идёт следом

M2 — бэкенд-фундамент: контракт `director.json`, хранилище, очередь джобов, слой провайдеров с учётом расходов, генерация типов из Pydantic. Черновики этапов — `docs/drafts/B0.2`–`B0.6`; устав `docs/tasks/M2.md` и сами этапы пишутся **после** M1, по итогам из `STATUS.md`. После M2 временные типы в `src/types/` заменяются генерацией, а фикстуры уступают место настоящим данным.

Порядок из `handoff/stack.md` ставит вторым модулем «Выпуски и календарь слотов» — это экранная работа поверх фикстур, её можно сделать и раньше бэкенда. Но тогда третьим идёт «Сценарий и план» с мостом через чат и валидацией JSON, а валидировать нечем без контракта. Дешевле взять фундамент сразу после оболочки, чем писать валидацию дважды.
