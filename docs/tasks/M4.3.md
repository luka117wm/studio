# M4.3 — Правки кадров, действующий план, версия из JSON

**Модуль:** M4 — Идеи, сценарий и план через мост · **Оценка:** 3 ч · **Модель:** Opus · **План до кода:** да

## Цель
Правки полей кадра пишутся в `user_override` типизированным PATCH. Действующий план (версия плюс правки) отдаётся
фронту готовым. План в JSON можно проверить без записи и сохранить новой версией с `source: manual`.

## Что сделать
1. **`ShotOverride`.**
   - Поля необязательны и повторяют типы плана. Проверки те же, что у плана: непустой `vo`, стоп-лист в
     `image.prompt`, диапазоны `motion`.
   - Ошибка — 422 в формате `кадр s003: …` (L-022: текст проверяется в тесте).
   - Правка кадра, которого нет в текущей версии, — 422.
2. **PATCH.** Правила мёрджа те же (словари рекурсивно). `ProjectPatch` закрывает хвост M2/M3: в теле только
   разрешённое. `brief` — как в M4.1.
3. **Действующий план** — чистая функция, без чтения диска внутри:
   - на копию версии накладываются правки;
   - у каждого кадра — `status`, `stale_reasons`, блокировки и список поправленных полей (`overridden: ["vo"]`);
   - в ответе: `version`, `source`, `approved_version` (пока `null`, появится в M4.6) и `facts`;
   - убранные (`removed`) кадры в конце с пометкой — их не теряем (принцип 8).
4. **`stale` от ручной правки.** Если у кадра уже есть картинка (`status: done`) и правка меняет поле, от которого
   зависит картинка (`image.prompt`, `image.shot_size`), кадр становится `stale` с причиной «Промпт изменён
   вручную». Картинок до M6 нет — правило закрепляется тестом.
5. **Новая версия поверх правок.** Мёрдж M2.4 правку не трогает: действующий план показывает правку поверх новой
   версии. Конфликт уже помечается `stale` правилом M2.4 — тест на связку «правка VO → новая версия с другим VO →
   правка на месте, кадр `stale` с причиной».
6. **Проверка без записи.**
   - `POST …/director/validate` — тело как у импорта. Для полного плана `canon_ref` и `voice` проверяются как есть;
     план из редактора несёт их из текущей версии.
   - Ответ: `{ok, errors[], items[]}`, `items` — для ссылок «к кадру» в редакторе.
7. **Версия из JSON** — `POST …/director?source=manual` тем же `import_plan`. Хэш совпал с текущей версией —
   `created: false`, как в M2.4.

## Критерии приёмки
- [ ] PATCH правки VO → в `project.json` только `user_override.vo` этого кадра; `null` сбрасывает; стилевой токен в
      правке промпта — 422 `кадр s003: …`
- [ ] PATCH с `director_version` или `assets` — 422 с читаемым текстом
- [ ] `GET …/plan` — правки наложены, `overridden` перечислен, `removed` — в конце
- [ ] правка VO + новая версия с другим VO → правка на месте, кадр `stale` с причиной
- [ ] `validate` возвращает `items` с `shot_id`; `?source=manual` → версия с `source: manual`
- [ ] `uv run pytest && uv run ruff check . && uv run mypy backend tests`; `typegen:check`

## Чего не делать
- не писать правки в файл версии: версии неизменяемы
- не сливать правки в новую версию автоматически: новая версия — только импорт или «Сохранить как версию»
- не открывать в `ShotOverride` поля канона (`image.period`, `image.appearances`) — их меняет новая версия плана
