# M1.4 — Клавиатура и фокус

**Модуль:** M1 — Оболочка · **Оценка:** 2 ч · **Модель:** Sonnet · **План до кода:** нет

## Цель
Всё в оболочке доступно с клавиатуры, глобальные сочетания работают, есть окно со списком клавиш.

## Читать
- `design/handoff/layout.md` — раздел про клавиатуру
- `design/Studio - 10 Состояния.dc.html` — блок с сочетаниями, если он там
- `frontend/src/app/AppShell.tsx`

## Создать / изменить
- `frontend/src/app/keyboard.ts` — реестр сочетаний с областями действия
- `frontend/src/app/KeyboardHelp.tsx` — диалог по `?`
- `frontend/src/app/useHotkey.ts` — хук подписки
- `frontend/src/app/__tests__/keyboard.test.tsx`

## Не трогать
- `frontend/src/ui/**`, `frontend/src/styles/**`

## Что сделать
1. Реестр, а не разбросанные слушатели: одно место, где перечислены сочетание, область, описание и обработчик. Из него же строится окно помощи — список клавиш не должен вестись отдельно, он разойдётся с реальностью на второй неделе.
2. Области: глобальная, экран, модальное окно. В открытом диалоге глобальные сочетания не срабатывают.
3. Минимум по `layout.md`: переходы между экранами, переключение канала, поиск, `?` — помощь, `Esc` — закрыть верхний слой. Что именно — брать из handoff, не придумывать.
4. Никаких сочетаний, перехватывающих браузерные (`Ctrl+W`, `Ctrl+T`, `Ctrl+N`).
5. В полях ввода одиночные буквенные сочетания не срабатывают.
6. Видимое кольцо фокуса на всём интерактивном, порядок обхода совпадает с визуальным.
7. Skip-link в начало рабочей области.

## Критерии приёмки
- [ ] `?` открывает помощь, список построен из реестра, не захардкожен
- [ ] в открытом диалоге глобальные сочетания не срабатывают, `Esc` закрывает
- [ ] в текстовом поле буквенные сочетания игнорируются
- [ ] Tab обходит оболочку в визуальном порядке, фокус всегда виден
- [ ] `pnpm -C frontend test` зелёный

## Команды проверки
```bash
pnpm -C frontend test --run
```

## Чего не делать
- не вводить сочетания, которых нет в handoff
- не вести список клавиш вторым местом
