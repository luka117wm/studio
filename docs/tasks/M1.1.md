# M1.1 — Токены и типографика

**Модуль:** M1 — Оболочка · **Оценка:** 3 ч · **Модель:** Opus · **План до кода:** да

## Цель
`tokens.css` подключён как единственный источник цветов, размеров и типографики, проброшен в Tailwind v4 через `@theme`, шрифты грузятся локально, базовый слой соответствует артбордам.

## Читать
- `design/handoff/tokens.css` — целиком, это основной вход
- `design/CLAUDE.md` — палитра, типографика, плотность
- `design/handoff/stack.md` — раздел про мост токенов в Tailwind
- `frontend/vite.config.ts`, `frontend/src/index.css`

## Создать / изменить
- `frontend/src/styles/tokens.css` — копия из handoff, не редактируется руками
- `frontend/src/styles/theme.css` — мост в `@theme`, отображение переменных в утилиты Tailwind
- `frontend/src/styles/base.css` — сброс, базовая типографика, фокус-кольцо, скроллбары
- `frontend/src/index.css` — точка сборки: импорт tailwind, tokens, theme, base, шрифты
- `frontend/scripts/sync-tokens.mjs` — копирование `design/handoff/tokens.css` → `src/styles/tokens.css` с проверкой изменений
- `package.json` — скрипт `tokens:sync`
- `frontend/src/styles/__tests__/tokens.test.ts`

## Не трогать
- `design/**` — только чтение
- любые компоненты: их ещё нет

## Что сделать
1. Скопировать `tokens.css` скриптом, а не руками. Скрипт должен уметь два режима: `--write` (скопировать) и `--check` (упасть, если файлы разошлись). Второй нужен, чтобы дрейф токенов ловился тестом, а не глазами.
2. В `index.css` порядок строго такой: `@import "tailwindcss";` → шрифты `@fontsource/*` → `tokens.css` → `theme.css` → `base.css`. Любой другой порядок даст переопределение переменных после их использования.
3. В `theme.css` — блок `@theme`, где каждой переменной из tokens присваивается имя утилиты Tailwind v4: цвета фона, панелей, линий, текста, цвета дорожек таймлайна, статусные цвета, радиусы, тени, размеры шрифтов, межстрочные. Имена утилит должны читаться так же, как имена в `design/CLAUDE.md`, чтобы макет и код назывались одинаково.
4. Не изобретать значения. Если чего-то в `tokens.css` нет, а в артборде оно есть — выписать список недостающего в конце работы, не подставлять свои числа.
5. Шрифты: IBM Plex Sans, IBM Plex Sans Condensed, Courier Prime — через `@fontsource`, только нужные начертания и латиница с кириллицей. Никакого Google Fonts: приложение обязано работать оффлайн.
6. `base.css`: сброс, `font-feature-settings` для табличных цифр в местах с числами, видимое фокус-кольцо по `:focus-visible`, тонкие скроллбары в тон панелей, `color-scheme: dark`.
7. Тест: `tokens:check` проходит; ни одного hex-литерала вне `tokens.css` (простая проверка регуляркой по `src/**`, исключая сам tokens).

## Критерии приёмки
- [ ] `pnpm -C frontend tokens:check` зелёный
- [ ] `pnpm -C frontend test` зелёный, включая проверку на hex вне tokens
- [ ] `pnpm -C frontend build` без предупреждений
- [ ] в devtools у `body` разрешаются переменные `--color-*` из tokens
- [ ] шрифты грузятся с локального origin (в Network нет запросов на fonts.googleapis.com)
- [ ] список недостающих в tokens значений выписан в конце сессии

## Команды проверки
```bash
pnpm -C frontend tokens:check
pnpm -C frontend test --run
pnpm -C frontend build
```

## Чего не делать
- не писать hex в компонентах и в `@theme` (только ссылки на переменные)
- не редактировать `src/styles/tokens.css` руками
- не подключать Tailwind по документации v3: конфиг-файла нет, всё через `@theme`
