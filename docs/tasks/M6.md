# M6 — Генерация: кадры выпуска, версии, кэш и проверка консистентности

Шестой модуль. Составлен 2026-10-21 по `STATUS.md` (разделы 42–53, «Дальше»), черновику `docs/drafts/B2A.5`,
артборду `design/Studio - 4 Генерация.dc.html` и решениям пользователя при составлении:
- панель «Голос» экрана 4 в M6 — заглушка на своём месте: голос — модуль M7;
- проверка консистентности: лицо — локально, OpenCV YuNet + SFace (лицензии MIT и Apache 2.0, CPU, $0),
  сходство с выбранным фасом облика; анахронизмы — дешёвая VLM Gemini Flash-Lite по `forbidden` эпохи, меньше
  $0.001 за кадр, выключатель в профиле канала. Только пометки, без блокировки;
- «Сделать опорным» и «Смягчить промпт через Claude» из артборда — вне M6: опорные — только листы и кадры стиля
  (принцип 13), отказ фильтра лечится «С правкой…», смягчение через Claude — в API-сессии;
- ручная приёмка — с настоящим Gemini, ~$2–3;
- хвосты, назначенные M6 (`STATUS.md`, «Дальше»), и скорость JSON-редактора входят в этапы.

Оценка: 44 часа, двенадцать этапов. Ветка `m6-generation` от `m5-canon` (PR M5 → `main`), тег `m6` на выходе.

**Что на выходе.** После «Утвердить план» у каждого кадра выпуска есть картинка по канону — с ценой до клика, в
очереди с паузой, без двойной оплаты, с версиями и подсказками, где персонаж перестал быть собой.
- **Пачка кадров.** «Сгенерировать N кадров (~$X)» ставит пачку джобов: смета и бюджет выпуска и месяца — суммой
  до постановки (принцип 6), параллельно не больше `images_parallel` запросов, пауза, продолжить, отмена,
  «Повторить упавшие». Прогресс — по SSE. Сбой кадра — `failed` с причиной, пачка идёт дальше (принцип 7).
- **Кадр как ассет с версиями.** Каждая отрисовка — новая версия `media/<кадр>/vNNN.<ext>` с миниатюрами webp
  160/320 (принцип 12). У кадра одна выбранная версия, остальные — в истории. «Перерисовать», «Добавить версию»,
  «С правкой…» (правка действия кадра и перерисовка), выбор версии.
- **Кэш по хэшу входов** (принцип 8): тот же запрос второй раз не платится, ассет из кэша привязывается к кадру
  так же, как оплаченный (L-042). Смена версии канона даёт другой хэш, кадр — `stale`, картинка остаётся.
- **Модель на пачку и кадр** — ключ каталога `images` (Nano Banana 2, 2 Lite, Pro) с ценой в кнопке; по умолчанию —
  профиль качества.
- **Проверка консистентности** готовых кадров: сходство лица с фасом облика (`consistency_low`), анахронизмы по
  `forbidden` (`anachronism_suspect`). Сетка «Подозрительные» по возрастанию сходства — первые десять, что смотрит
  человек.
- **Экран 4 «Генерация»** по артборду: полоса очередей 72, панель «Канон выпуска» 280 (только чтение), сетка
  кадров по разделам (5 / 6 / 8 в ряд), выбор и полоса выбора с моделью и ценой, действия кадра, «Сравнение версий»,
  панель «Голос» 320 — заглушка до M7.
- **План после генерации** (хвосты M4, M5): смета без уже нарисованного, отчёт импорта с датой и ценой картинки,
  правка кадра после утверждения, сходство по действующему плану, быстрый JSON-редактор на больших планах.

**Чего на выходе нет и не должно быть.**
- **Голоса, выравнивания, таймлайна** — M7; панель «Голос» и вторая дорожка полосы очередей — заглушки.
- **Анимации кадров** — M8. **Апскейла** (Real-ESRGAN) — позже, со своим модулем.
- **«Сделать опорным»** и **«Смягчить промпт через Claude»** — решение пользователя (выше).
- **Блокировки по пометкам проверки.** Пометка — подсказка человеку, не цензор: ни генерация, ни монтаж, ни
  публикация по ней не останавливаются.
- **Тихой замены модели.** Превышение бюджета — явный отказ; отказ фильтра — `failed` с текстом, не повтор на
  другой модели.
- **Удаления картинок.** Версии кадра не удаляются: `stale`, история, выбор другой версии.
- **Claude API** — по-прежнему только мост (устав M4).

## Решения модуля

Приняты при составлении, чтобы этапы не спорили о них заново.

1. **Хранение — по `CLAUDE.md`, «Структура» и «Данные».**
   - Картинка версии — `data/projects/<канал>/<выпуск>/media/<кадр>/vNNN.<ext>`, расширение — по MIME ответа
     модели (L-039). Миниатюры — `media/<кадр>/thumbs/vNNN-160.webp`, `-320.webp` (`storage/thumbs.py`, M5.9).
   - `project.json → assets{}` — строка на версию (`kind: image`, `version`, `path`, `hash`, `status`), плюс
     метаданные версии: модель, seed, вариант, цена, когда нарисована, результаты проверок. Выбранная версия —
     новое поле `ShotState.image_version` (`int | null`). Контракт — новый `docs/generation.md` (M6.1), строка в
     карте `CLAUDE.md`.
   - Кадр без картинки при новой версии плана или переводе канона **не** становится `stale`: устаревать нечему.
     Он остаётся `todo`, причина пишется в историю (хвост M5.2, раздел 43).
2. **Запрос кадра** — `pipeline/images/prompt_builder.build_shot_request` (M5.5) без изменений порядка секций.
   - Новая версия — тот же запрос с номером варианта: `seed = seed_of(…, variant)`. Вариант 1 — первая отрисовка,
     «Перерисовать» и «Добавить версию» берут следующий свободный. Перезапуск джоба после аварии рисует тот же
     вариант — из кэша за $0.
   - Есть `problems` сборщика — кадр не ставится, отказ со списком проблем и адресатами (M5 хвосты: `canon`).
3. **Джоб кадра `shot_image`** — один кадр, один вариант.
   - Платный, с `episode_id`, `batch_id`, `estimate` по маршруту `images` выбранной модели. Шлюз: `cached` или
     `charged` (принцип 6), строка `cost_ledger` этапа `images` с кадром.
   - Попадание в кэш привязывает ассет к кадру новой версией так же, как оплаченный вызов (L-042).
   - Отказ фильтра безопасности и прочие `ProviderError` — кадр `failed` с текстом модели по-русски
     («Отказ фильтра безопасности: насилие — смягчите действие кадра»), без повтора. Сеть и 5xx — повтор очереди.
   - После картинки — проверки (решение 7) тем же джобом: лицо всегда, VLM — если включена в профиле.
4. **Пачка** — `POST /api/projects/{id}/generate` `{shots?, model?, redraw?}`.
   - Без `shots` — все кадры без выбранной картинки и `stale`; `redraw: true` — новый вариант и у готовых.
   - Смета и бюджет — **суммой** до постановки: не влезает — 409 `BudgetRefusal` с суммой пачки, ни одного джоба
     (хвост M4, раздел 38). Кэш в смете не вычитается — оценка сверху, как у листов.
   - Пачка — строка `batches` (миграция): выпуск, модель, создана, пауза. Пауза — пул не берёт `queued` джобы
     пачки, идущие доделывают. Отмена — `cancel` всех незаконченных, начатые дорисуются.
   - Параллельность — `images_parallel` (по умолчанию 3, не больше `job_workers`): у вида джоба — лимит
     одновременных, общий пул не растёт.
   - «Повторить упавшие» — новая пачка из `failed` кадров последней пачки, тот же вариант.
   - Один кадр в двух незаконченных пачках — 409 с id пачки.
5. **Стадия и статус выпуска** (`docs/episodes.md`): стадия остаётся `generate` (переход в монтаж — M7/M8).
   Статус: идёт пачка — `generating`; у всех кадров выбрана картинка, сбоев и пометок нет — `ready`; есть `failed`
   или пометки проверки — `warning`. Утверждение и статусы, по которым доска рисует колонку, — без изменений.
6. **Модель** — ключ каталога `images` (`config/providers.yaml`): на пачку (полоса выбора экрана 4) и на кадр
   (версия помнит свою модель). По умолчанию — профиль качества канала; настройка профиля на экране 9 — M11.
   Цена в кнопке — по каталогу выбранной модели, а не по артборду ($0.034 у Lite в `pricing.yaml`).
7. **Проверка консистентности** — пометки, не блокировка (решение пользователя, черновик `B2A.5`).
   - **Лицо.** OpenCV `FaceDetectorYN` (YuNet) + `FaceRecognizerSF` (SFace) из `opencv-python-headless` (уже в
     стеке). Веса — ONNX из opencv_zoo (YuNet — MIT, SFace — Apache 2.0) скачивает команда
     `python -m app.tools.fetch_models` в `data/models/` с проверкой sha256 из конфига; без весов проверка лица
     пропускается с предупреждением, а не падает. Эталон — выбранный фас листа облика той версии, к которой прибит
     выпуск. На каждый облик кадра — лучшее косинусное сходство среди найденных лиц; ниже порога
     (`config/checks.yaml`, мягкий по умолчанию) — `consistency_low`; лиц не найдено (спина, общий план) —
     `no_face`, «не проверено», не подозрение.
   - **Анахронизмы.** Новый этап `check` (`kind: vision`) в `config/providers.yaml`: Gemini Flash-Lite, цена — в
     `pricing.yaml` с датой проверки. Один запрос на версию кадра: картинка + `forbidden` эпохи кадра, ответ строго
     `{"found": [...]}`. Непусто — `anachronism_suspect` со списком. Строка `cost_ledger` этапа `check`.
     Выключатель — `profile.json → checks.anachronism` (по умолчанию включено), выключенный не платит и не
     пишет пометок.
   - Результаты — у версии ассета; «Подозрительные» — версии выбранные, по возрастанию сходства.
   - `POST …/shots/{id}/check` — перепроверка выбранной версии (джоб `shot_check`), например после включения VLM.
8. **Экран 4** — по артборду и `layout.md`.
   - Ширины: канон 280 (тянется 240–360, `⌥1`), центр `1fr`, «Голос» 320 (`⌥3`); полоса очередей 72; полоса выбора
     44. Сетка — 5 в ряд на 1536, 6 на 1920, 8 на 2560; заголовки разделов `sticky`.
   - Полоса очередей: «Кадры: 78 из 104», осталось ~N мин, потрачено из сметы, «параллельно 3 запроса», ошибки,
     пауза, отмена; вторая дорожка «Голос» — «модуль M7».
   - Плитка: миниатюра 16:9, номер, глиф статуса (`design/CLAUDE.md`), точки версий, пометки проверки; наведение —
     «Перерисовать», «С правкой…», «Открыть в монтаже»; у `failed` — причина и те же действия.
   - Выбор: клик, ⇧-клик — диапазон, ⌘A; полоса выбора — сегменты модели с ценой и «Перерисовать выбранные (N,
     ~$X)». Клавиши — R перерисовать кадр, V версии кадра (статус-строка артборда).
   - «Сравнение версий» — режим заголовка: версии кадра с моделью, seed, временем, ценой, «Соответствие канону»
     (сходство лица), «Выбрать версию N», «Добавить версию (~$0.07)».
   - Пустое состояние до первой пачки — «Сгенерировать N кадров (~$X)» (главное действие экрана), до утверждения —
     «План не утверждён» со ссылкой на экран 3 (принцип 10).
9. **План после генерации** (хвосты M4, разделы 34, 38, 41).
   - Новая текущая версия плана на стадии `generate` по-прежнему возвращает выпуск в `script` (утвердить снова);
     перерисовываются только изменённые кадры — смета утверждения считает кадры без валидной картинки, не все.
   - Правка кадра на листе после утверждения (`user_override`) разрешена: кадр с картинкой — `stale` с причиной,
     утверждение не сбрасывается — это не новая версия плана.
   - Отчёт импорта (`ShotChange`) получает `drawn_at` и `price` выбранной версии: «картинка 12:41, $0.067 —
     станет stale».
   - Сходство с референсом при утверждении считается по действующему плану (с правками), а не по файлу версии.
   - JSON-редактор: подсветка только видимых строк (виртуализация), ввод на плане 100+ кадров — меньше 16 мс.
10. **Фронт — как в M5.** TanStack Query, прогресс — SSE (`api/live.ts`), моки `mocks/api.ts` пополняются кадрами
    «Пиратов» артборда 4 (104 кадра, 8 разделов, версии, два отказа фильтра). e2e — на моках, поток SSE — `e2e/events.ts`
    (M5.11). Эталоны экрана 4 переснимаются один раз — в M6.12.
11. **Тесты.** Сеть замокана (Gemini — фейковым транспортом, как в M5.3). Логика проверки лица — на фейковом
    эмбеддере; настоящие веса — `pytest -m models` вручную после `fetch_models`, на фикстурах `tests/fixtures/faces/`
    — свои картинки, один раз нарисованные нашим Gemini (~$0.40), не чужие фото. Живые: `-m live -k shot_image` —
    один кадр, центы; `-m live -k vision_check` — один запрос.
12. **Контракты.**
    - Новый: `docs/generation.md` (M6.1) — версии кадра, пачка, статусы, API, проверки.
    - Правки: `docs/project_schema.md` (`image_version`, метаданные ассета), `docs/jobs.md` (`shot_image`,
      `shot_check`, пачка, пауза, лимит вида), `docs/providers.md` (этап `check`, модель на пачку и кадр),
      `docs/episodes.md` (статус на стадии `generate`), `docs/director_schema.md` (кадр без картинки не `stale`).

> Прочитай `CLAUDE.md`, `design/CLAUDE.md`, `docs/LESSONS.md` и `docs/tasks/M6.x.md`. Больше ничего не читай, пока не составишь план на 6–10 пунктов со списком файлов. Жду «ок» от меня перед кодом.

`design/CLAUDE.md` — для UI-этапов (M6.7–M6.12); для M6.12 — без последних двух предложений.

## Приёмка M6 целиком

Перед `git tag m6`:

- [ ] двенадцать этапов закрыты, коммит на каждый
- [ ] `uv run pytest && uv run ruff check . && uv run ruff format --check . && uv run mypy backend tests` — зелёные
- [ ] `pnpm -C frontend test --run && lint && build && typegen:check && tokens:check && e2e` — зелёные; эталоны
      экрана 4 пересняты только в M6.12, каждое изменение — строка в `docs/visual_review.md`
- [ ] одинаковый запрос кадра второй раз — `cached`, $0, ассет привязан новой версией (тест); сбой кадра не
      останавливает пачку (тест); пачка сверх бюджета — 409 суммой, ни одного джоба (тест)
- [ ] пометки проверки ничего не блокируют: утверждение, генерация и стадия выпуска от них не зависят (тест)
- [ ] вручную: `./run.sh` + seed, настоящий Gemini (~$2–3):
  - **подготовка:** выпуск из 12 кадров с одним обликом, лист облика 6/6 (настоящий, ~$1.61, если живого нет);
  - **пачка:** экран 4 → «Сгенерировать 12 кадров (~$0.80)» → прогресс по SSE, «параллельно 3 запроса» → пауза:
    новые не стартуют, начатые дорисовываются → продолжить → 12 картинок, миниатюры, строки `cost_ledger` этапа
    `images` с кадрами;
  - **кэш:** повтор пачки тем же вариантом (сбросить выбор в API) — `cached`, $0;
  - **версии:** «Перерисовать» кадр → версия 2 → «Сравнение версий» → выбрать версию 1 → в монтаж идёт она;
    «С правкой…» → новое действие → версия 3;
  - **модель:** выбранные 2 кадра на Lite → цена в кнопке по каталогу → версии с моделью Lite;
