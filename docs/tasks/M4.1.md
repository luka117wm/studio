# M4.1 — Мост: промпты, разбор ответа, журнал обменов, заявка

**Модуль:** M4 — Идеи, сценарий и план через мост · **Оценка:** 4 ч · **Модель:** Opus · **План до кода:** да

## Цель
Бэкенд собирает промпт задачи моста из шаблона и контекста, принимает вставленный ответ чата, достаёт из него JSON
или объясняет по-русски, что не так, и пишет каждый обмен в журнал. У выпуска появляется заявка — вход промпта
плана.

## Что сделать
1. **Шаблоны.**
   - Каталог шаблонов передаётся загрузчику параметром: в приложении — `backend/app/prompts/`, в тестах — фикстурный.
   - Рендер детерминирован: тот же контекст даёт тот же текст и хэш.
   - Значения подставляются как есть. JSON-фрагменты контекста сериализует код (`json.dumps(…, indent=2,
     ensure_ascii=False)`), не шаблон.
2. **`extract_json(text)`** возвращает объект или поднимает `BridgeAnswerError` с `message` и `hint`. Правила:
   - один блок ```json (или ``` без языка) — берётся он; два и больше — ошибка «В ответе N JSON-блоков, ожидался
     один», подсказка: попросить чат прислать одним блоком;
   - блока нет — первый сбалансированный `{…}`; скобки внутри строк и экранирование учитываются;
   - объект не закрыт — «Ответ обрывается на строке N», подсказка: написать чату «continue» и вставить ответ
     целиком или уменьшить часть;
   - синтаксическая ошибка — строка и столбец по исходному тексту ответа, не по вырезанному куску;
   - пусто или JSON нет вовсе — свои тексты.

   Ничего не «чинить» молча: ни запятые, ни кавычки.
3. **Журнал `bridge_runs`.**
   - Поля: `id`, `task`, `channel`, `episode_id` (null), `target_id` (null — например, референс), `prompt_id`,
     `prompt_version`, `prompt_hash`, `part`, `parts_total`, `status`
     (`prompted | applied | failed`), `errors` (JSON), `created_at`, `answered_at`.
   - Функции: `open_run(…)` при выдаче промпта, `close_run(id, status, errors)` при приёме ответа, `latest_runs(…)`.
     Ответ без открытого обмена тоже принимается — обмен открывается и закрывается сразу (вставка из старого чата).
   - Строк в `cost_ledger` мост не пишет — тест.
4. **`plan_source`.**
   - В `providers.yaml` — `bridge | api`, по умолчанию `bridge`. Неизвестное значение — ошибка старта с текстом.
   - `api` при пустом `ANTHROPIC_API_KEY` не ломает старт: `GET /api/bridge/settings` отдаёт
     `api: {available: false, reason: "Нет ключа ANTHROPIC_API_KEY — docs/api_keys.md"}`, и мост остаётся
     единственным путём.
5. **Заявка.**
   - Поля `Brief`: `idea`, `angle`, `hook_promise`, `notes` (строки, могут быть пустыми), `sources[]` (`title`,
     `url`), `idea_id`, `reference_id`, `reference_mode` (`none | structure_clone | own_version`).
   - Пустой проект — `brief: null`. PATCH с `brief` создаёт заявку, лишние поля — 422.
6. **Ошибки ответа для пользователя.** Формат `BridgeError {message, hint, errors[]}`, статус 422. Тексты — по-русски,
   без извинений (`CLAUDE.md`, «Соглашения»). Тест сверяет тексты, а не только статус (L-022).
7. **`docs/bridge.md`:**
   - что такое задача моста, шаблоны и front-matter, правило версии промпта (меняется текст — растёт `version`);
   - правила разбора ответа с примерами;
   - журнал, `plan_source`, API;
   - почему нет строк расхода.

## Критерии приёмки
- [ ] рендер фикстурного шаблона детерминирован; нехватка или лишний ключ контекста — ошибка с именем ключа
- [ ] `extract_json` — таблица случаев: блок ```json с прозой вокруг, ``` без языка, голый объект, два блока, скобки
      в строках, обрезанный ответ (номер строки), синтаксическая ошибка (строка и столбец), пустой ответ, ответ без
      JSON
- [ ] `bridge_runs`: открыть → закрыть `applied` / `failed` с ошибками; `latest_runs` по выпуску и задаче
- [ ] `GET /api/bridge/settings` без ключа: `plan_source: bridge`, API недоступен с причиной
- [ ] `PATCH /api/projects/{id}` с `brief` сохраняет заявку; лишнее поле — 422 с читаемым текстом
- [ ] `uv run pytest && uv run ruff check . && uv run mypy backend tests`; `pnpm -C frontend typegen:check`

## Чего не делать
- не вызывать Anthropic и не писать «авто-режим», который сам ходит в чат
- не «чинить» JSON эвристиками: неправильный ответ — понятная ошибка
- не хранить ответы чата целиком в БД: ошибки — да, текст ответа — нет (план ляжет файлом версии в M4.2)
- не добавлять зависимости: front-matter — простой YAML через уже подключённый `pyyaml`
