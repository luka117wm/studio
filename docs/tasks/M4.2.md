# M4.2 — План через мост: части, `canon_ref` и `voice` из кода, импорт

**Модуль:** M4 — Идеи, сценарий и план через мост · **Оценка:** 4 ч · **Модель:** Opus · **План до кода:** да

## Цель
Для выпуска с заявкой бэкенд выдаёт промпт части k из N. Принимает ответ чата, подставляет `canon_ref` и
`voice`, проверяет и копит части. После последней части план импортируется версией `vNNN` механизмом M2.4, а
выпуск из стадии «Идея» переходит в «Сценарий».

## Что сделать
1. **Раскладка частей.**
   - `parts_total = ceil(shots / shots_per_part)` по пресету канала: Cursus — 100 кадров → 4 части, Otto — 40 → 2.
   - Часть k получает диапазон id кадров: часть 1 — `s001…s026`, часть 2 — `s027…s052` и т. д.; последняя — до
     конца плана.
   - Число частей фиксируется в обмене: промпт части 1 начинает новый набор (как импорт M2.4).
2. **Промпт части 1** (`plan_first.md`) получает из кода:
   - канал, формат, пресет (минуты, разделы, кадры, темп);
   - заявку; `episode_id`; `part` / `parts_total` и диапазон кадров;
   - для референса — блок структуры, пока `none` (наполнит M4.10).

   Правила для чата:
   - ровно один блок ```json `studio.director/1` и скелет полей;
   - `canon_ref` и `voice` не писать — их подставит приложение;
   - `image.prompt` — только действие, композиция, ракурс; категории стоп-листа перечислены словами;
   - формат id эпох и обликов;
   - `facts[]` со статусом, `source_url` и `shot_id` — чат проверяет факты веб-поиском;
   - части 2…N продолжат тот же план.
3. **Промпт части k** (`plan_next.md`) — короткий: продолжить с id `sNNN`. Конспект принятых частей: разделы с id
   и заголовками, последний кадр, сколько кадров уже есть. Те же правила формата — ссылкой на часть 1 и кратким
   повтором ключевых.
4. **Приём ответа:**
   - `extract_json` (M4.1);
   - сверка: `meta.episode_id` и `meta.channel` — этого выпуска, `meta.part` — ожидаемой части, `parts_total` — как в
     наборе. Расхождение — 422 с понятным текстом: «Это часть 3, ожидалась часть 2 — скопируйте промпт части 2»;
   - подстановка: `voice` — из профиля канала, модель — маршрут `voice` профиля по умолчанию из `providers.yaml`
     (принцип 5); `canon_ref` — `style/v001`, эпохи и облики из ссылок кадров с `v001`. Части 2…N — без подстановки:
     их возьмёт сборка M2.4 из части 1;
   - если чат всё же прислал `canon_ref` или `voice`, их заменяет код, и в отчёте об этом есть строка;
   - проверка `validate_director` и далее путь M2.4: часть копится или план собирается и импортируется
     (`source: bridge`);
   - обмен закрывается `applied` / `failed` с ошибками.
5. **Ответ API** — `PlanAnswerResult`: что принято (часть k из N, сколько кадров в части), что дальше (следующая
   часть или итог импорта `ImportResult`) и предупреждения (подменённые блоки, факты без источника).
6. **Стадия.** Успешный импорт при стадии `idea` переводит выпуск в `script`. Остальные стадии здесь не меняются:
   возврат из `generate` — M4.6.
7. **Эталоны промптов.** Рендер для фикстурного выпуска сверяется с файлами в `tests/fixtures/prompts/`. Меняется
   шаблон — растёт `version` и обновляется эталон. Тест падает, если текст изменился, а версия нет.
