# M5.2 — Канон выпуска: прибитые версии, «нужно каналу», перевод, ворота утверждения

**Модуль:** M5 — Канон · **Оценка:** 4 ч · **Модель:** Opus · **План до кода:** да

## Цель
План выпуска ссылается на настоящие опубликованные версии канона и не прыгает на новые сам. Канал видит, каких эпох
и обликов из его планов не хватает. Перевод выпуска на новые версии — явное действие. «Утвердить план» отказывает,
пока канон и листы не готовы.

## Что сделать
1. **`canon_ref` новой версии плана** (решение 3):
   - id, прибитые в прошлой версии плана, сохраняют версию;
   - новые id получают последнюю опубликованную версию;
   - нет версии — заготовку `v001`.
   Действует и для плана из моста (части), и для «Сохранить как версию».
2. **Канон выпуска** — `GET …/canon`: стиль, эпохи и облики плана. По каждому:
   - прибитая версия и последняя опубликованная;
   - статус: `missing` — нет версии, `draft_only` — есть только черновик, `ready`, `outdated` — есть новее;
   - у облика — статус листа (`missing` до M5.4).
   Итог `ready: bool` и список проблем по-русски.
3. **«Нужно каналу»** — id из `canon_ref` планов выпусков канала без опубликованной версии: какие выпуски и сколько
   кадров ссылаются. `POST …/needed/{kind}/{id}` создаёт скелет-черновик. Персонаж облика создаётся, если его нет.
4. **Перевод на новые версии** — `POST …/canon/update`:
   - новая версия плана `source: manual`, тот же текст, `canon_ref` — последние опубликованные;
   - затронутые кадры — `stale` с причиной по `canon_reasons` (M2.4), картинки не удаляются;
   - нечего обновлять — 200 без новой версии, как совпавший хэш в M4.7.
   После утверждения новая версия возвращает стадию в `script` (правило M4.6).
5. **Проверка `canon` при утверждении** (решение 8):
   - стиль, эпохи и облики резолвятся в опубликованные версии;
   - у облика лист 6/6 и не устарел.
   Проблемы — `ApprovalProblem{check: "canon", shot_id: null, message}` с id сущности. Сводка — «Канон не готов: 1
   эпоха не опубликована, у 2 обликов нет листа — экран «Канон»».
6. **Планы M4 с заготовками `v001`** без файлов канона импортируются, как раньше. Канон выпуска показывает их как
   `missing`, утверждение отказывает — это и есть ворота.
7. Документы:
   - `director_schema.md` — откуда берутся версии в `canon_ref`;
   - `project_schema.md` — перевод на новые версии и `stale`;
   - `episodes.md` — проверка `canon` в утверждении;
   - `canon_schema.md` — «нужно каналу».
8. Тесты:
   - новая версия плана сохраняет прибитую эпоху, хотя есть новее;
   - новый облик получает последнюю версию;
   - перевод даёт `stale` с причиной;
   - утверждение — отказ `canon` с id и успех после публикации (лист — заглушка статуса до M5.4);
   - «нужно каналу» по двум выпускам.
