# M2.1 — Каркас бэкенда и хвосты M0

**Модуль:** M2 — Бэкенд-фундамент · **Оценка:** 2 ч · **Модель:** Sonnet · **План до кода:** нет

## Цель
`uv run pytest`, `uv run ruff check .` и `uv run mypy backend` работают на чистом проекте, настройки читаются из
`backend/.env`, API собран из роутеров, остатки `uv init` убраны.

## Читать
- `pyproject.toml`, `backend/app/main.py`, `backend/.env.example`, `run.sh`
- `docs/drafts/B0.1.md` — блок «Статус» с хвостами M0

Больше ничего не открывать. Нужен файл вне списка — сначала сказать.

## Создать / изменить
- `pyproject.toml` — убрать `[project.scripts]` и `uv_build`, `[tool.uv] package = false`; конфиг ruff
  (line-length 100, правила E, F, I, UP, B), mypy strict для `backend/app`, pytest (`testpaths`, `pythonpath = ["backend"]`,
  `asyncio_mode = "auto"`, маркер `live`)
- `backend/app/settings.py` — `Settings` на pydantic-settings: `STUDIO_DATA_DIR` (по умолчанию `<репозиторий>/data`),
  ключи провайдеров (пустые по умолчанию), `env_file = backend/.env`
- `backend/app/api/__init__.py` — агрегатор роутеров; `backend/app/api/health.py` — `/api/health` переезжает сюда
- `backend/app/main.py` — фабрика приложения, CORS, логирование (`logging`, без `print`), подключение агрегатора
- `backend/app/log.py` — конфиг логов: уровень из настроек, формат с временем и модулем
- `tests/conftest.py` — `TestClient`, временный `STUDIO_DATA_DIR` в `tmp_path`
- `tests/test_health.py`
- `.gitignore` — проверить `data/`, `backend/.env`, `.venv`, `__pycache__`
- удалить `src/studio/`

## Не трогать
- `frontend/**` — оболочка закрыта тегом `m1`
- `run.sh` — только проверить, что поднимает оба процесса после изменений

## Что сделать
1. Вычистить `pyproject.toml` от `uv init`: скрипт `studio`, `uv_build`, `src/`; проект — приложение, не пакет.
2. Конфиги ruff, mypy, pytest в `pyproject.toml`; `uv run ruff check .` и `uv run mypy backend` на текущем коде чисты.
3. `Settings` с `STUDIO_DATA_DIR`; путь разворачивается через `Path.expanduser().resolve()`, каталог создаётся при старте.
   Решить расхождение: `.env.example` говорит `~/studio-data`, `CLAUDE.md` — `data/` в репозитории (gitignored);
   принять `CLAUDE.md`, поправить `.env.example`.
4. Агрегатор роутеров и `health.py`; `main.py` — `create_app()`.
5. Логирование через `logging.config.dictConfig`, uvicorn использует тот же формат.
6. `conftest.py` с фикстурой клиента и изолированным `data`-каталогом; `test_health.py`.
7. `./run.sh` — проверить запуск и остановку по Ctrl+C.

## Критерии приёмки
- [ ] `uv run pytest -q` зелёный (≥ 1 тест), `uv run ruff check .`, `uv run mypy backend` чисты
- [ ] `curl localhost:8000/api/health` → `{"status":"ok","version":"0.1.0"}`
- [ ] `src/studio/` нет, `uv sync` не пытается собрать пакет
- [ ] `STUDIO_DATA_DIR` из `backend/.env` переопределяет путь, каталог создаётся

## Команды проверки
```bash
uv sync && uv run pytest -q && uv run ruff check . && uv run mypy backend
./run.sh   # health по curl, Ctrl+C гасит оба процесса
```

## Чего не делать
- не добавлять зависимости следующих этапов (httpx уже есть для тестов, tenacity — в M2.5, PyYAML — в M2.6)
- не создавать пустые папки «на будущее» (`models/`, `jobs/`, `providers/` появятся в своих этапах)
