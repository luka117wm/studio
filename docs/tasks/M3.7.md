# M3.7 — Визуальная приёмка и e2e на моках API

**Модуль:** M3 — Выпуски и календарь слотов · **Оценка:** 3 ч · **Модель:** Sonnet · **План до кода:** нет

## Цель
E2E идёт на моках API. Эталоны оболочки и экрана 1 пересняты один раз и сверены с артбордом 1. Сквозной сценарий
«создать выпуск → увидеть в слоте и на доске → переименовать» проходит в браузере.

Больше ничего не открывать. Нужен файл вне списка — сначала сказать.

## Создать / изменить
- `frontend/e2e/api.ts` — `mockApi(page)`:
  - `page.route('**/api/**')` отвечает из `src/mocks/api.ts`, `POST`/`PUT`/`PATCH` меняют состояние мока на время
    теста;
  - `/api/events` — пустой поток с `retry: 600000` (без переподключений в снимках);
  - незамоканный путь — падение теста с именем пути, не молчаливый 404
- `frontend/e2e/visual.spec.ts` — `open()` ставит `mockApi` и часы на `2026-09-11T12:41` («сегодня» и «Сохранено
  12:41» артборда); экраны 2–12 открывают выпуск `pirate` из моков
- `frontend/e2e/episodes.spec.ts` — сквозной сценарий на 1536: диалог → создание → тост → сценарий → «Выпуски»:
  карточка в «Сценарии» и выпуск в ближайшем пустом слоте → переименование в шапке → «Сохранено»
- `frontend/e2e/__screenshots__/` — пересъёмка (`--update-snapshots`) после сверки
- `docs/visual_review.md` — раздел «M3, экран 1 и шапка»: каждая разница с артбордом — «совпадает / осознанно /
  правка handoff»

## Что сделать
1. Моки и сценарий зелёные до пересъёмки: сначала `episodes.spec.ts`, потом снимки.
2. Сверка на 1536, снимки и замеры DOM с обеих сторон, как в M1.6:
   - шапка: переключатель 109px с аватаром, название, индикатор, расход;
   - заголовок экрана; полоса слотов (ячейки ≥ 96, «сегодня», риск, пропущен);
   - колонки и карточки (64×36, отступы 8, прогресс 2px);
   - диалог «Новый выпуск».

   Расхождение — исправить или записать с причиной.
3. Пересъёмка: `pnpm -C frontend e2e --update-snapshots`, затем три прогона подряд без расхождений. Изменились все
   экраны, потому что шапка общая: в коммите перечислить, что именно поменялось, а не «обновил снимки».
4. Экраны 2–12 в снимках — те же заглушки. Отличаются только шапкой (переключатель и название выпуска из моков).
   Любая другая разница — дефект M3.3–M3.6.
5. Ручной прогон на живом бэкенде (`./run.sh` + seed): пункты «вручную» приёмки модуля. Результат — в `STATUS.md`.

## Критерии приёмки
- [ ] `pnpm -C frontend e2e` зелёный три раза подряд; `episodes.spec.ts` в их числе
- [ ] незамоканный запрос валит тест (проверено временно убранным моком, не коммитить)
- [ ] `docs/visual_review.md` — раздел M3 без открытых строк; цвет «Опубликован» и прочие правки handoff — в списке
      правок перед M4 (`STATUS.md`, раздел M1.6)
- [ ] `pnpm -C frontend test --run && lint && build && typegen:check` зелёные

## Команды проверки
```bash
pnpm -C frontend e2e --update-snapshots   # один раз, после сверки
for i in 1 2 3; do pnpm -C frontend e2e || break; done
```

## Чего не делать
- не поднимать порог `threshold` / `maxDiffPixels` (L-012)
- не ходить из e2e в настоящий бэкенд — снимки должны быть детерминированы
- не переснимать эталоны «до зелёного» без сверки
