# Канон канала: схемы, черновики, версии, ссылки

Контракт M5.1. Модели — `backend/app/models/canon.py`, хранилище — `backend/app/storage/canon_store.py`, API —
`backend/app/api/canon.py`. TS-типы — `frontend/src/types/canon.ts` (ответы) и `canon_draft.ts` (тела `PUT`),
генерируются `pnpm -C frontend typegen`. Сборка промпта из канона — `docs/prompt_assembly.md` (M5.5).

Канон — визуальная константа уровня канала, а не выпуска (`CLAUDE.md`, «Данные»; принципы 13 и 14). Три слоя,
каждый версионируется отдельно: стиль канала, эпохи, персонажи с обликами. План выпуска канон не содержит —
только ссылки `canon_ref` на версии.

## Хранение

```
data/channels/<channel>/canon/
  style/                    v001.json  v002.json …  draft.json
  periods/<period_id>/      v001.json …             draft.json
  characters/<character>/   v001.json …             draft.json     один файл на персонажа со всеми обликами
  anchors/<appearance_id>/  candidates/  rejected/  sheet.json  chosen.json    лист опорных портретов (M5.4)
  anchors/style/            *.jpg  sheet.json  chosen.json                    опорные кадры стиля (M5.4)
```

- **Версия** `vNNN.json` (`v001`…`v999`) неизменяема. Пишется только новым файлом: temp → fsync → `os.link` →
  unlink temp (`storage/atomic.py::write_json_new`). Если файл уже есть — отказ, а не замена. Версии не правятся
  и не удаляются.
- **Черновик** `draft.json` — один на слой или сущность. Пишется атомарно поверх (L-003). Проверяется только
  форма (422), правила публикации — нет.
- Каналы изолированы: всё лежит под `data/channels/<channel>/`, канон одного канала другому не виден.

Конверт файла:

```jsonc
// vNNN.json
{ "based_on": "v001",            // версия, из которой начат черновик; null — с нуля
  "published_at": "2026-10-14T12:00:00+00:00",
  "data": { … } }                // Style | Period | Character
// draft.json
{ "based_on": "v001", "saved_at": "2026-10-14T11:58:02+00:00", "data": { … } }
```

Номер версии — из имени файла, в конверте его нет.

## Поля

Текст всех полей, кроме подписей `label`, — **английский**: он уходит в промпт картинки (принцип 13). Подписи
`label` — по-русски, они только для экрана. У всех полей есть пустые значения по умолчанию: скелет из одного
`id` — годный черновик.

### Стиль — `Style` (`style/vNNN.json`)

Один на канал, одинаков для всех выпусков. Группы — как в артборде 12, слой «Стиль».

| Поле | Тип | Что это |
|---|---|---|
| `render` | str | «Рендер и материал»: техника изображения |
| `material` | str | фактура поверхностей |
| `processing` | str | обработка: кривая, контраст, резкость |
| `optics.focal` | str | «Оптика»: фокусное, высота камеры |
| `optics.depth` | str | глубина резкости |
| `optics.distortion` | str | дисторсия |
| `light.character` | str | «Свет»: характер, источники |
| `light.contrast` | str | контраст |
| `light.direction` | str | направление |
| `palette.rule` | str | «Палитра»: правило |
| `palette.swatches[]` | `{role: str, hex: "#RRGGBB"}` | образцы, 3–5 |
| `grain` | str | «Зерно и композиция»: зерно |
| `composition` | str | композиционные правила |
| `negative_global` | str[] | глобальный negative канала |

### Эпоха — `Period` (`periods/<id>/vNNN.json`)

Факты времени и места, переиспользуются между выпусками.

| Поле | Тип | Что это |
|---|---|---|
| `id` | str | `[a-z0-9][a-z0-9-]*`, совпадает с каталогом: `caribbean-1716` |
| `label` | str | подпись на экране, по-русски: «Карибы, 1716» |
| `region` | str | регион |
| `years` | `{from: int, to: int}` \| null | годы, `from ≤ to` |
| `palette_shift` | str[] | сдвиг палитры эпохи |
| `materials` | str[] | материалы |
| `light_sources` | str[] | источники света |
| `architecture` | str[] | архитектура и транспорт |
| `clothing` | str[] | одежда |
| `props` | str[] | предметы |
| `forbidden` | str[] | анахронизмы: идут в negative каждого кадра эпохи (L-007) |

### Персонаж — `Character` (`characters/<id>/vNNN.json`)

| Поле | Тип | Что это |
|---|---|---|
| `id` | str | `[a-z0-9][a-z0-9-]*`, совпадает с каталогом: `you` |
| `label` | str | имя на экране, по-русски |
| `nature.personality` | str | характер |
| `nature.posture` | str | осанка |
| `nature.manner` | str | манера |
| `nature.face` | str | черты лица — неизменяемы во всех обликах |
| `appearances[]` | `Appearance` | облики |

### Облик — `Appearance` (внутри персонажа)

| Поле | Тип | Что это |
|---|---|---|
| `id` | str | `<персонаж>@<облик>`: `you@powder-monkey-11`, префикс — id персонажа, без повторов |
| `label` | str | подпись на экране, по-русски |
| `period` | str | id эпохи облика |
| `age` | int \| null | полных лет, 0–120 |
| `build` | str | телосложение |
| `face` | str | уточнение к `nature.face` для этого облика: возраст, загар, борода |
| `hair` | str | волосы |
| `clothing` | str | одежда |
| `wear` | str | износ и повреждения |
| `props` | str[] | предметы облика |
| `negative_local` | str[] | negative облика |

## Черновик и публикация

1. `PUT …/draft` — черновик целиком. `based_on` берётся у прежнего черновика, а без него — последняя версия
   (правят то, что видят), без версий — `null`.
2. `POST …/draft?from=vNNN` — черновик из любой версии («Создать v004 из v002»). Если черновик уже есть — 409:
   его не затираем.
3. `POST …/publish` — правила публикации → `v<N+1>.json` → черновик удаляется. При отказе черновик остаётся как
   был, версия не пишется.
4. `DELETE …/draft` — сбросить черновик. Версии не трогаются.

**Правила публикации** (`publish_problems()`, отказ 409 со всеми нарушениями сразу):

| Слой | Правило |
|---|---|
| стиль | непустой `render`; 3–5 образцов палитры; у каждого образца есть `role` |
| эпоха | непустые `label` и `region`; есть `years`; `forbidden` — хотя бы одна позиция |
| персонаж | непустые `label` и `nature.face`; хотя бы один облик |
| облик | непустые `label` и `period` |
| все | нет кириллицы в полях промпта (всё, кроме `label`); нет пустых позиций в списках |
| все | черновик отличается от последней версии — иначе публиковать нечего |

## Ссылки из плана

Формат ссылок проверяет `CanonRef` (`models/director.py`), резолв — `canon_store`:

| Ссылка | Функция | Результат |
|---|---|---|
| `style/v003` | `resolve_style(paths, channel, ref)` | `Style` |
| `periods/caribbean-1716/v002` | `resolve_period(paths, channel, ref)` | `Period` |
| `characters/you/v004#captain-35` | `resolve_appearance(paths, channel, ref)` | `(Character, Appearance)`, облик `you@captain-35` |

Ссылка резолвится только в опубликованную версию, черновик ссылкой не достать. Канон выпуска (M5.2) считает
статусы ссылок плана по снимку канона канала — `docs/project_schema.md`, «Канон выпуска». Ошибка — `CanonRefError` (`.ref` —
исходная ссылка). Текст — фрагмент со строчной буквы, чтобы импорт плана (M5.2) мог приставить кадр:

- `стиль style/v003 не найден в каноне cursus`
- `эпоха periods/caribbean-1716/v002 не найдена в каноне cursus`
- `персонаж characters/you/v004 не найден в каноне cursus`
- `облик you@captain-35 не найден в characters/you/v004`
- `ссылка «periods/caribbean-1716/v1» не по формату periods/<эпоха>/vNNN`

## API

Префикс `/api/canon/{channel}`. Неизвестный канал — 404 «Канал … не найден» (`require_channel`). Слои:
`style`, `periods/{period_id}`, `characters/{character_id}`. Набор запросов у всех одинаковый.

| Запрос | Тело / параметры | Ответ |
|---|---|---|
| `GET /api/canon/{channel}` | — | `CanonSummary` |
| `GET …/{слой}` | `?version=vNNN`; без него — черновик, а без черновика — последняя версия | `StyleDoc` \| `PeriodDoc` \| `CharacterDoc` |
| `PUT …/{слой}/draft` | `Style` \| `Period` \| `Character` целиком | документ черновика, 200 |
| `POST …/{слой}/draft?from=vNNN` | — | документ черновика, 201 |
| `DELETE …/{слой}/draft` | — | 204 |
| `POST …/{слой}/publish` | — | документ новой версии, 201 |

Документ слоя: `{draft, version, based_on, updated_at, data}`. У черновика `draft: true`, `version: null`,
`updated_at` — `saved_at`. У версии `updated_at` — `published_at`.

`CanonSummary`:

```jsonc
{ "channel": "cursus",
  "style": { "versions": [{ "version": "v001", "based_on": null, "published_at": "…" }], "draft": false },
  "periods": [{ "id": "caribbean-1716", "label": "Карибы, 1716", "region": "Caribbean Sea, Nassau",
                "years": { "from": 1716, "to": 1726 }, "versions": […], "draft": true,
                "forbidden_count": 12, "episodes": 3 }],
  "characters": [{ "id": "you", "label": "Ты", "versions": […], "draft": false, "appearances_count": 3,
                   "sheets_ready": 2 }] }
```

Подпись, регион, годы и счётчики берутся из черновика, а без него — из последней версии. В список попадают только
каталоги, где есть черновик или версия. Счётчики экрана 12 (M5.8, `episode_canon.canon_overview`):

- `episodes` — сколько выпусков канала ссылаются на эпоху текущей версией плана: в `canon_ref` или хотя бы в одном
  кадре (то же правило, что у контекста моста эпохи). Выпуски без плана не считаются.
- `sheets_ready` — у скольких обликов персонажа (из черновика, без него — из последней версии) лист опорных
  портретов `ready`: 6/6 и не устарел против последней опубликованной версии персонажа, где облик есть (раздел
  «Устаревание»). Облик без опубликованной версии листа не имеет.

## Нужно каналу

M5.2 (устав M5, решение 2). Планы ссылаются на эпохи и облики раньше, чем те появились в каноне: план из моста
получает заготовки `v001` (`docs/director_schema.md`, «Откуда версии»). «Нужно каналу» собирает такие id, из них
создаются скелеты. Логика — `pipeline/canon/episode_canon.py → canon_needed`, API — `api/canon.py`.

| Запрос | Ответ |
|---|---|
| `GET /api/canon/{channel}/needed` | `CanonNeeded` |
| `POST /api/canon/{channel}/needed/periods/{period_id}` | `PeriodDoc` черновика, 201 |
| `POST /api/canon/{channel}/needed/appearances/{appearance_id}` | `CharacterDoc` черновика персонажа, 201 |

**Что нужно.** Эпохи и облики из `canon_ref` **текущих** версий планов выпусков канала, у которых нет ни одной
опубликованной версии (у облика — ни одной версии персонажа, где он есть). Черновик не считается: эпоха с черновиком
в списке остаётся, с пометкой `draft: true`. Стиль в список не входит: он один на канал и виден в своём слое и в
каноне выпуска. Выпуски без плана пропускаются; битый файл одного выпуска — предупреждение в лог, как на доске.

```jsonc
{ "channel": "cursus",
  "periods": [{ "id": "venice-1570", "draft": false, "shots": 31,          // кадров во всех выпусках
                "episodes": [{ "id": "c09-galley", "title": "Галера", "shots": 31 }] }],
  "appearances": [{ "id": "you@comito-34", "draft": false, "shots": 12, "episodes": […],
                    "character_exists": true }] }   // персонаж есть — облик допишется в его черновик
```

Порядок — по id; выпуски — как на доске (по дате слота, без слота — в конце).

**Скелет** — черновик с одним id, остальные поля пустые (годный черновик, но не публикуемый):

- **эпоха** — `draft.json` с `{id}`, `based_on: null`;
- **облик** — в черновик персонажа `<персонаж>` дописывается `{id: <облик>}`. Черновика нет — он начинается с
  последней версии персонажа (`based_on` — она); персонажа нет — создаётся `{id, appearances: [{id}]}`.

Отказы — 409, ничего не пишется:
- `Эпоха caribbean-1716 уже опубликована (v001) — создавать её не нужно.`
- `У эпохи venice-1570 уже есть черновик — откройте его на экране «Канон» и опубликуйте.`
- `Облик you@captain-35 уже опубликован в characters/you/v001 — создавать его не нужно.`
- `Облик you@comito-34 уже есть в черновике персонажа you — откройте его на экране «Канон» и опубликуйте.`

id не по формату — 422 с текстами раздела «Ошибки»; неизвестный канал — 404.

## Черновик эпохи из моста

M5.6 (устав M5, решение 4). Черновик эпохи может написать чат: промпт `canon_period` по id эпохи из планов и
заявкам выпусков, ответ — в `draft.json` эпохи. Публикует человек, обычным «Опубликовать» с правилами раздела
«Черновик и публикация». Стиль канала и облики из моста не приходят (принцип 13). Контракт задачи моста, контекст,
проверки и API — `docs/bridge.md`, «Эпоха».

| Режим | Что меняется в черновике |
|---|---|
| `draft` | пустые поля (`""`, `null`, `[]`) — из ответа; заполненные человеком — как были, несовпадения — `conflicts` |
| `forbidden` | `forbidden` — новые позиции в конец, без повторов (регистр, артикли `a/an/the`, пробелы, знак в конце) |

Основа — черновик, без него последняя версия (её номер становится `based_on`), без неё — скелет с `id`. «Дополнить
запреты» без черновика и версий — 409.

| Запрос | Ответ |
|---|---|
| `POST …/periods/{period_id}/prompt?mode=draft\|forbidden` | `PeriodPrompt` |
| `POST …/periods/{period_id}/answer?mode=draft\|forbidden` `{text}` | `PeriodAnswerResult` с документом черновика |

## Листы опорных портретов

M5.4 (устав M5, решения 1, 5, 6). Эталон внешности облика: 6 ракурсов × кандидаты, человек выбирает по одному на
ракурс. Дальше лист подаётся референсом в каждый кадр с этим обликом (M5.5, M6). Код — `pipeline/canon/anchors.py`,
джобы — `jobs/handlers/anchors.py` (`docs/jobs.md`, «Джобы опорных»), настройки — `config/canon.yaml`.

**Ракурсы** (набор фиксирован, подписи и строки кадрирования — в конфиге):

| id | Подпись | Соотношение | Референс |
|---|---|---|---|
| `front` | Фас | 3:4 | — |
| `three_quarter` | Три четверти | 3:4 | фас |
| `profile` | Профиль | 3:4 | фас |
| `full_body` | В полный рост | 2:3 | фас |
| `in_action` | В действии | 2:3 | фас |
| `detail` | Деталь | 1:1 | фас |

**Из чего собирается промпт** — код, а не LLM (принцип 13). Шаблон `prompts/anchor_sheet.md` (`task: image`),
секции по порядку:

1. `Rendering` — стиль канала (последняя опубликованная версия): `render`, `material`, `processing`, палитра
   (`rule` и образцы `роль #hex`), `grain`. Свет, оптику и композицию лист не берёт: у эталона свои нейтральный фон
   и ровный свет.
2. `Era` — эпоха облика (последняя версия): `region`, `years`, `materials`, `clothing`, `props`.
3. `Person` — неизменяемое персонажа и облик (последняя версия персонажа, где облик есть): `age`, `nature.face` +
   `face`, `build`, `hair`, `clothing`, `wear`, `props`, `posture`, `manner`, `personality`.
4. `Framing` — строка ракурса из конфига и требования эталона: серый студийный фон, ровный свет, без людей и текста.

Negative — `negative_global ∪ forbidden ∪ negative_local`, без повторов (без учёта регистра), порядок стабильный.
Подписи `label` в промпт не идут. Стиль, эпоха или облик не опубликованы — «Собрать лист» отвечает 409 с тем, что
опубликовать. Черновики в лист не идут.

**Seed** — sha256 от (облик, версия персонажа, ракурс, номер кандидата), 31 бит. «Собрать лист» всегда рисует номера
1…k (`candidates` из конфига, 2): повторная сборка без изменений даёт те же промпты и seed — 12 строк `cached`, $0.
«Перегенерировать ракурс» берёт следующие номера (3, 4, …), поэтому кандидаты новые.

**Фас-референс** — выбранный фас той же версии персонажа, а без выбора — первый удавшийся по времени. Референсом
служит только фас этого же облика; у фасов и кадров стиля референсов нет.

### Файлы набора

- `candidates/<ракурс>-<n>-<хэш16>.<ext>` — файл кандидата; имя без расширения — **id кандидата**. Хэш — хэш входов
  вызова (`docs/providers.md`), расширение — по ответу модели (Pro отдаёт JPEG, L-039).
- `rejected/` — отбракованные: файл переезжает сюда, строка `assets` — вслед за ним (кэш помнит оплаченное, а
  повторная сборка не вернёт кандидата в `candidates/`). Ничего не удаляется.
- `sheet.json` — все кандидаты всех сборок:

```jsonc
{ "target": "you@powder-monkey-11",
  "candidates": [{ "id": "front-1-3f9ab2c4d5e6f7a8", "slot": "front", "n": 1,
                   "status": "ready",                      // ready | rejected | failed
                   "file": "candidates/front-1-3f9ab2c4d5e6f7a8.jpg",   // от каталога набора; у failed — null
                   "error": null, "seed": 1234567, "version": "v001",   // версия персонажа
                   "canon": { "style": "style/v003", "period": "periods/caribbean-1716/v002",
                              "appearance": "characters/you/v001#powder-monkey-11" },
                   "ref": null,                            // id фаса-референса
                   "usd_micro": 134000, "cached": false, "job_id": "…", "created_at": "…" }] }
```

  Повтор из кэша запись не меняет. Запись о сбое того же кандидата (ракурс, номер, версия) заменяет новая попытка.
- `chosen.json` — выбор: ракурс → кандидат, файл, seed, версия персонажа, дата выбора, цена.

```jsonc
{ "target": "you@powder-monkey-11",
  "slots": { "front": { "candidate": "front-2-…", "file": "candidates/front-2-….jpg", "seed": 7654321,
                        "version": "v001", "canon": { … }, "chosen_at": "…", "usd_micro": 134000 } } }
```

Выбор только из `ready` с файлом на месте. Выбранного не отбраковать — сначала выбрать другого. Лист одного облика
другому не подходит: каталог — по id облика.

### Устаревание

Выбор ракурса сравнивается с версией персонажа: на экране — с последней опубликованной, где облик есть; в каноне
выпуска (`EpisodeCanon.appearances[].sheet`, M5.2) — с версией, к которой прибит выпуск.

| Изменилось между версией выбора и текущей | Что устарело |
|---|---|
| `nature.face`, `face`, `build`, `hair`, `age` | весь лист |
| `clothing`, `props`, `wear` | «В полный рост», «В действии», «Деталь» |
| остальное (подписи, `negative_local`, …) | ничего: лист переходит на новую версию как есть |

`hair`, `age` и `wear` в таблицу добавил этап M5.4: устав называл только черты лица, телосложение, одежду и предметы.
Статус листа: `missing` — ничего не выбрано; `outdated` — хоть один выбор устарел; `partial` — выбрано меньше 6;
`ready` — 6/6 и ничего не устарело. «Утвердить план» требует `ready` (`docs/episodes.md`).

### Копия облика в другую эпоху

`POST …/appearances/{id}/copy {period, appearance_id}` дописывает в черновик персонажа новый облик: тот же человек в
другой эпохе или другом возрасте. Источник — черновик персонажа, без него — последняя версия.

- побайтово переносятся `face`, `build`, `hair`, `age`, `negative_local`; неизменяемое (`nature`) у персонажа общее;
- `label`, `clothing`, `wear`, `props` — пустые: их пишут заново; листа у копии нет.

Отказы: облика-источника нет — 404; id копии уже есть — 409 «Облик you@squire-14 уже есть в персонаже you —
выберите другой id копии.»; id копии другого персонажа — 422 «Облик otto@squire-14 не принадлежит персонажу you —
id облика начинается с «you@».».

## Опорные кадры стиля

Шесть кадров стиля канала (`config/canon.yaml → style_frames`: общий план, портрет, деталь, толпа, ночь, силуэт),
16:9, по одному кандидату, эпоха — из запроса. Шаблон `prompts/style_anchor.md`: стиль целиком (с оптикой, светом и
композицией), эпоха целиком (с палитрой, светом эпохи и архитектурой), строка шаблона. Negative —
`negative_global ∪ forbidden`. Seed — от (версия стиля, эпоха и её версия, шаблон). Файлы — `canon/anchors/style/`,
`sheet.json` и `chosen.json` — как у листа; удавшийся кадр выбирается сразу, и из кэша тоже: пересборка в
прежней эпохе возвращает выбор на её кадры (L-042). Кадр выпуска берёт кадры стиля только своей эпохи
(`docs/prompt_assembly.md`).

Устаревают при смене рендера (`render`, `material`, `processing`), оптики (`optics.*`) или света (`light.*`) между
версией стиля кадра и последней опубликованной. Палитра, зерно, композиция и negative кадры не устаревают.

## API опорных

Префикс `/api/canon/{channel}`; неизвестный канал — 404, id облика не по формату — 422 (раздел «Ошибки»).

| Запрос | Тело | Ответ |
|---|---|---|
| `GET /appearances/{id}/anchors` | — | `AnchorSetState` листа |
| `GET /appearances/{id}/anchors/estimate` | — | `AnchorsEstimate`: строки `sheet`, `angle`, `style` (`EstimateLine`) |
| `POST /appearances/{id}/anchors` | — | `Job` `anchor_sheet`, 201 |
| `POST /appearances/{id}/anchors/{angle}/regenerate` | — | `Job` `anchor_angle`, 201 |
| `POST /appearances/{id}/anchors/{angle}/choose` | `{candidate}` | `AnchorSetState` |
| `POST /appearances/{id}/anchors/{angle}/reject` | `{candidate}` | `AnchorSetState` |
| `POST /appearances/{id}/copy` | `{period, appearance_id}` | `CharacterDoc` черновика, 201 |
| `GET /style/anchors` | — | `AnchorSetState` кадров стиля |
| `GET /style/anchors/estimate` | — | `AnchorsEstimate` — та же смета без облика, для «Пересобрать (6, ~$0.80)» |
| `POST /style/anchors` | `{period}` | `Job` `style_anchors`, 201 |

`AnchorSetState`: `channel`, `target` (облик или `style`), `version` (с чем сравнивается выбор; null — облик не
опубликован), `status`, `chosen`, `total`, `stale` (сводка: «Лист устарел: в v004 изменились face — пересоберите
лист.», «Устарели ракурсы «В полный рост», «В действии», «Деталь»: в v003 изменились clothing — перегенерируйте их.»),
`slots[]` (`slot`, `label`, `hint`, `candidates[]`, `chosen`, `stale` — «в v003 изменились clothing»), `spent` —
оплачено за все кандидаты. Пути файлов в ответе — от `data/`; показ картинок на экране — M5.9.

Смета — сверху, кэш не вычитается: «6 ракурсов × 2 кандидата» $1.61, «2 кандидата» $0.27, «6 кадров» $0.80 при цене
Pro 1K $0.134. Постановка проверяет месячный бюджет канала — 409 с телом `BudgetRefusal` (`docs/providers.md`), и
один набор — один джоб: второй — 409 «Лист you@powder-monkey-11 уже собирается (джоб …) — дождитесь окончания или
отмените его.»

Отказы 409 и 404 листа (тело `{"detail": "…"}`):
- `Стиль канала не опубликован — опубликуйте его на экране «Канон», потом собирайте опорные.`
- `Облик you@powder-monkey-11 не опубликован — опубликуйте персонажа с этим обликом на экране «Канон», потом собирайте лист.`
- `Эпоха caribbean-1716 облика you@powder-monkey-11 не опубликована — опубликуйте её на экране «Канон».`
- `Для ракурса «Профиль» нужен фас облика you@powder-monkey-11 (v001) — соберите лист или перегенерируйте фас.`
- `Кандидат front-1-… отбракован — выберите другого.` · `Кандидат front-1-… выбран для ракурса «Фас» — выберите другого, потом отбракуйте этого.`
- 404: `Ракурса «sideways» в листе нет — есть: front, three_quarter, profile, full_body, in_action, detail.` ·
  `У ракурса «Фас» облика … нет кандидата … — обновите лист.`

## Ошибки

Одна фраза: что случилось и что сделать.

- **422 — форма.** Тело FastAPI: `detail[]` с `loc` и `msg`. Тексты — `PydanticCustomError` (L-022):
  - `id «Venice_1570» не годится — только строчные латинские буквы, цифры и дефис, например caribbean-1716.`
  - `id облика «captain-35» не годится — нужен вид <персонаж>@<облик>, например you@powder-monkey-11.`
  - `Облик otto@london-1666 не принадлежит персонажу you — id облика начинается с «you@».`
  - `Облик you@captain-35 повторяется — у каждого облика свой id.`
  - `Цвет «brown» не годится — нужен код #RRGGBB, например #2b2118.`
  - `Образцов палитры 6, а можно не больше 5 — уберите лишние.`
  - `Годы эпохи наоборот: from 1580 позже to 1570 — поменяйте их местами.`
  - `Возраст 300 вне 0–120 — укажите полных лет.`
  - `Версия «2» не годится — нужна вида v001.` (`?version=`, `?from=`)
  - `id «caribbean-1716» в теле не совпадает с адресом «venice-1570» — исправьте одно из двух.`

  Ошибки типов (строка вместо числа) и лишние поля — стандартные тексты pydantic.
- **409 — правило публикации или конфликт.** Тело `{"detail": "…"}`; несколько нарушений — через `\n`:
  - `Эпоха без запретов не публикуется — добавьте хотя бы один анахронизм.`
  - `Персонаж без обликов не публикуется — добавьте хотя бы один облик.`
  - `Поле light.direction написано по-русски — текст канона уходит в промпт картинки, пишите по-английски.`
  - `Пустая позиция в списке forbidden — заполните или удалите её.`
  - `Черновик эпохи caribbean-1716 не отличается от v001 — публиковать нечего, сбросьте черновик.`
  - `У эпохи caribbean-1716 уже есть черновик — опубликуйте или сбросьте его, потом создавайте черновик из v002.`
  - `У эпохи caribbean-1716 нет черновика — публиковать нечего.`
  - `Версия v002 эпохи caribbean-1716 уже есть — опубликованные версии не перезаписываются, обновите страницу.`
- **404 — нет сущности или версии.** Тело `{"detail": "…"}`:
  - `Эпохи venice-1570 в каноне cursus нет — создайте черновик.`
  - `У эпохи caribbean-1716 нет версии v009 — есть: v001, v002.`
  - `У эпохи caribbean-1716 нет черновика — сбрасывать нечего.`
