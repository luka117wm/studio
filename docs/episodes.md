# Выпуски — контракт API и таблицы `episodes`

Выпуск — строка в таблице `episodes` (SQLite) плюс каталог `data/projects/<channel>/<id>/` с `project.json`
(`docs/project_schema.md`). Модели — `backend/app/api/episodes.py`, сводка карточки —
`backend/app/models/episode_summary.py`, типы фронта — `@/types/episode`.

## Поля выпуска (`Episode`)

| Поле | Тип | Описание |
|---|---|---|
| `id` | `^[a-z0-9][a-z0-9-]*$` | имя каталога, глобально уникален (не только в канале); после создания не меняется |
| `channel` | `cursus \| otto` | канал; не меняется |
| `title` | str, 1…200 после `strip` | название; меняется через `PATCH` |
| `short_title` | str ≤ 40 \| `null` | короткое имя для ячейки слота; пустая строка = `null` |
| `origin` | `backlog \| reference \| blank` | откуда выпуск: из бэклога идей, по референсу, с нуля; задаётся при создании |
| `stage` | `idea \| script \| generate \| edit \| export \| publish` | где выпуск в пайплайне (шесть этапов рельса) |
| `status` | `queued \| generating \| warning \| ready \| failed \| published` | здоровье выпуска на его стадии |
| `slot_date` | `YYYY-MM-DD` \| `null` | слот публикации; в слоте один выпуск (уникальный индекс); правила — `docs/slots.md` |
| `created_at`, `updated_at` | ISO 8601 UTC, секунды | `updated_at` растёт при каждой правке |

Ответы API — `EpisodeListItem` = `Episode` + `summary` (ниже): так отвечают список, `GET /api/episodes/{id}`,
`POST` и `PATCH`, и кэш фронта хранит одну форму.

### Стадия и статус

- **Стадия** меняется только действиями пайплайна. Ручной смены стадии нет — ни в API, ни в интерфейсе.
  - Создание выпуска ставит начальную стадию (таблица ниже).
  - Импорт плана (M4.2, `mark_plan_imported` в `api/episodes.py`) переводит `idea` → `script` — и мостом через чат, и
    ручным `POST …/director`, в том числе повторный импорт того же плана.
  - «Утвердить план» (M4.6) → `generate`, раздел «Утверждение плана» ниже.
  - Новая текущая версия плана (M4.6) возвращает утверждённый выпуск `generate` → `script`: утвердить нужно снова,
    `approved_version` остаётся историей. Повторный импорт того же плана версию не меняет и стадию не трогает.
  - Поздние стадии (`edit` и дальше) импорт не трогает: что делать с планом после начала генерации, решит M6.
- **Статус** — здоровье на текущей стадии:
  - `queued` — ждёт следующего шага или очереди (так выпуск создаётся);
  - `generating` — на стадии идёт работа;
  - `warning` — стадия прошла, но есть что проверить руками;
  - `ready` — стадия закончена, можно дальше;
  - `failed` — стадия упала, нужен повтор;
  - `published` — ролик на YouTube.
- **Колонка доски** — не поле, а чистая функция фронта от стадии и статуса (M3.5, с тестом):
  - статус `published` → «Опубликован» при любой стадии;
  - `idea` → «Идея», `script` → «Сценарий», `generate` → «Генерация», `edit` → «Монтаж»;
  - `export` → «Монтаж», пока рендер не готов; `export` со статусом `ready` и стадия `publish` → «Готов к
    публикации».

  Правило сверяется с артбордом 1 в M3.5; расхождение — туда же, в тест функции.

### Происхождение и начальная стадия

| `origin` | Стадия при создании | Кто шлёт |
|---|---|---|
| `blank` (по умолчанию) | `script` | диалог «Новый выпуск», «С нуля» |
| `reference` | `script` | диалог, «По референсу»; с M4.10 — `POST /api/references/{id}/episodes` (`docs/research.md`, «Выпуск по референсу») |
| `backlog` | `idea` | API принимает с M3; интерфейс — с M4 (бэклог идей) |

Статус при создании — `queued`.

## Id выпуска

- Без `id` в теле сервер выдаёт `{инициал канала}{NN}`: `c01`, `c02` у Cursus, `o01` у Otto; после `c99` — `c100`.
- Номер — наибольший среди id вида `c\d+` (для Otto — `o\d+`) плюс один. Id глобален, поэтому номер ищется по всей
  таблице. Id вида `c07-pirate-ship` в нумерацию не входят.
- Номер, занятый каталогом без строки в БД (след аварии), пропускается: авто-id не падает с 409.
- Выбор номера, создание каталога и `INSERT` — одна транзакция `BEGIN IMMEDIATE`: параллельный `POST` из другого
  соединения ждёт коммита первого и получает следующий номер.
- Явный `id` по-прежнему принимается: шаблон, 409 на существующий выпуск (в любом канале) и на существующий каталог.

## API

### `GET /api/episodes?channel=`

Без `channel` — оба канала (режим «Все каналы»). Порядок: `slot_date` по возрастанию, выпуски без слота — в конце
по `created_at`. Журнал расходов и джобы читаются одним запросом на весь список, `project.json` и текущая версия
плана — по разу на выпуск. Битый или пропавший файл одного выпуска не роняет список: в лог — предупреждение,
в сводку — нули (без плана) или то, что удалось прочитать.

### `POST /api/episodes` → 201 `EpisodeListItem`

Тело `EpisodeCreate`: `channel` (обязательно), `id`, `title` (по умолчанию «Новый выпуск»), `short_title`,
`origin` (по умолчанию `blank`), `slot` (по умолчанию `next_free` — ближайший свободный слот после сегодняшнего;
дата `YYYY-MM-DD` или `null`, правила — `docs/slots.md`), `idea_id` (M4.8). Ошибки: 404 — канала нет
(`PYTHONPATH=backend uv run python -m app.tools.seed`), 409 — id, каталог или слот заняты, 422 — поля или дата не из расписания.

**Из идеи** — `{channel, origin: "backlog", idea_id}`: идея этого канала и в бэклоге (`docs/research.md`, «Выпуск из
идеи»). Название — идеи, если `title` не прислан; заявка `project.json → brief` — из идеи (`idea` ← название,
`angle`, `hook_promise`, `notes` ← `summary`, `idea_id`); стадия `idea`. Идея → `used` с `episode_id` в той же
транзакции `BEGIN IMMEDIATE`, что выбор id и слота. Ошибки: 404 — идеи нет, 422 — идея другого канала или
`idea_id` без `origin: backlog`, 409 — идея не в бэклоге. Отказ не оставляет ни каталога, ни строки.

### `GET /api/episodes/{id}` → `EpisodeListItem`; 404 — выпуска нет.

### `PATCH /api/episodes/{id}` → `EpisodeListItem`

Тело `EpisodePatch`: `title`, `short_title`. Поля нет в теле — не меняется; `short_title: null` (или пустая
строка) — сброс. `updated_at` ставит сервер. Ошибки:
- 422 — пустое название, `title: null`, длиннее лимита;
- 422 с текстом «через PATCH не меняются» — `id`, `channel`, `origin`, `stage`, `status`;
- 422 — любое другое лишнее поле (`slot_date` меняет `PUT /api/episodes/{id}/slot`, `docs/slots.md`);
- 404 — выпуска нет.

Текст 422 показывается пользователю: одна ошибка на поле в `detail[].msg`, по-русски, «что случилось и что сделать».

### `POST /api/episodes/{id}/approve` → `EpisodeListItem` — утверждение плана

Кнопка «Утвердить план» на экране 3 (устав M4, решения 7 и 8; принцип 10). Тела нет.

1. **Проверки** — список `CHECKS` в `pipeline/script/approve.py`, каждая возвращает проблемы `{check, shot_id,
   message}`:
   - `stage` — стадия не позже `generate`;
   - `plan` — версия плана есть; без неё и с недособранным набором частей — чего не хватает. Набор частей при готовой
     версии не мешает: утверждается версия;
   - `vo`, `prompt` — у каждого кадра действующего плана (версия плюс правки), кроме `removed`, непустые VO и
     `image.prompt`;
   - `similarity` (M4.10, принцип 11) — выпуск с `brief.reference_id`: доля n-грамм VO плана, найденных в
     субтитрах референса, не выше порога `config/reference.yaml` (`docs/research.md`, «Сходство»).
2. **Отказ** — 409, `detail` — `ApprovalRefusal` `{code: "plan_not_ready", message, problems}`. `message` —
   сводка: проблемы плана как есть, проблемы кадров числом и id по проверке, первые 8 id и «и ещё N»: «2 кадра без VO:
   s003, s007 — допишите на листе сценария или в таблице плана и утвердите снова.» Ничего не пишется.
3. **Успех** — `approved_version` = текущая версия и `approved_at` в `project.json` (`docs/project_schema.md`),
   затем стадия `generate`. Повтор для уже утверждённой версии на стадии `generate` — 200 без записи.

Утверждение не ставит джобов и не резервирует бюджет — это очередь генерации M6. Смету до клика отдаёт
`GET /api/projects/{id}/estimate` (`docs/providers.md`, «Смета плана»). Правка кадра после утверждения стадию не
меняет: действующий план изменится, а `approved_version` — нет (хвост к M6 в `STATUS.md`).

## Сводка карточки (`EpisodeSummary`)

Считается при каждом чтении, в БД не хранится.

| Поле | Единица | Как считается |
|---|---|---|
| `shots_total` | кадры | кадры текущей версии плана (`project.director_version`), кроме `removed` |
| `shots_done`, `shots_failed`, `shots_stale`, `shots_generating` | кадры | по `status` в `project.json`; `todo` и `queued` входят только в total; кадра нет в `project.json` — `todo` |
| `vo_words` | слова | VO тех же кадров; слово — буквы и цифры, апостроф внутри (`don't`), тире и многоточия не считаются |
| `duration_s` | секунды, float, до мс | первое, что есть: см. `duration_source` |
| `duration_source` | `voice \| estimate \| target \| null` | `voice` — сумма `timings`, если у **каждого** кадра тайминг измерен голосом или задан вручную (`voice`, `locked`); `estimate` — слова при 150 слов/мин; `target` — `target_minutes × 60` плана без слов; `null` — плана нет |
| `spent_usd_micro` | микродоллары | сумма строк журнала выпуска со статусами `charged` + `estimated` (`SPENT_STATUSES`); `cached`, `refused`, `failed` не входят |
| `job` | `EpisodeJob \| null` | джоб выпуска со статусом `running`, иначе самый свежий `queued`: `kind`, `status`, `progress` (0…1), `message` |

Без плана — все счётчики кадров и слов 0, `duration_s` и `duration_source` — `null`; расход и джоб считаются как
обычно (сценарий мог уже стоить денег).
